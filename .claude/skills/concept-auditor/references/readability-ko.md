# 한국어 기술 문서 가독성 기준

이 사이트의 본문은 처음 배우는 사람이 읽는 기술 문서다. 아래 기준은 문장 단위의 가독성을 본다. 문체 규칙(한다체, 비유 금지, 용어 표기)은 [편집 안내](../../../../docs/contributing/content-authoring.md)를 따른다.

## 수치 기준

2026-11-24 전체 152개 레슨의 본문 문장(문단 기준)을 `audit:content`로 잰 값이다.

| 지표 | 사이트 현재 값 | 기준 |
| --- | --- | --- |
| 평균 문장 길이(공백 포함) | 약 50자 | 레슨 평균 60자 이하 |
| 긴 문장(120자 초과) 비율 | 레슨 평균 약 1% | 레슨마다 10% 이하 |
| 긴 문단(450자 초과) | 11개 레슨에 있음 | 문단 하나에 생각 하나, 450자를 넘으면 나눌 곳을 찾는다 |

글자 수만으로 판단하지 않는다. 짧아도 기호와 새 용어가 몰린 문장이 더 어렵다.

## 문장

- **한 문장에 내용 하나.** 길게 이은 문장은 의미 전달을 방해하므로 짧은 문장 여러 개로 나눈다(국립국어원 「쉬운 공공언어 쓰기」의 문장 나누기 원칙). 특히 "~하고, ~하며, ~하는데, ~해서"가 세 번 이상 이어지면 나눈다.
- **주어와 서술어를 가깝게.** 주어 뒤에 긴 관형절이 붙으면 서술어를 찾기 어렵다.
- **명사 나열을 줄인다.** "모델의 출력의 분포의 평균"처럼 "의"가 세 번 이어지면 풀어 쓴다.
- **번역투를 줄인다.** "~에 있어서" → "~에서", "~를 통해" → "~로", "~하는 것이 가능하다" → "~할 수 있다", "~를 가지고 있다" → "~가 있다", "~되어진다" → "~된다". `audit:content`가 후보를 보여 준다.
- **이중 피동을 쓰지 않는다.** "보여지다", "되어지다".
- **부정을 겹치지 않는다.** "~하지 않는 것은 아니다".

## 용어와 기호

- **첫 사용 때 정의한다.** 정의는 그 문장 안이나 바로 다음 문장에 둔다. 영어 원어는 첫 정의에 한 번 병기한다(예: 가능도(likelihood)).
- **수식의 기호는 수식 바로 뒤에서 설명한다.** "여기서 $\eta$는 학습률, $\nabla L$은 손실의 기울기다."
- **같은 개념에 같은 용어를 쓴다.** 한 레슨 안에서 "특성"과 "피처", "가중치"와 "파라미터"를 섞지 않는다(가중치는 파라미터의 한 종류다).
- **약어는 처음에 풀어 쓴다.** "MSE(평균제곱오차)".

## 구성

- **소제목은 내용을 말한다.** "개요", "더 알아보기"보다 "곱하는 순서가 결과를 바꾼다"처럼 결론을 담는다.
- **표와 목록은 비교·절차에 쓴다.** 이유와 인과는 문장으로 쓴다.
- **코드 셀 앞에 무엇을 확인할지 한 문장으로 말한다.** 셀 뒤에는 결과가 무엇을 보여 주는지 말한다.
- **주의 콜아웃은 짧게.** 세 문장 이내, 오해와 올바른 설명과 근거만 둔다.

## 이 사이트에서 감점하지 않는 것

- 영어 기술 용어(attention, self-attention, dropout)를 본문에 영어로 쓰는 것은 편집 안내의 표기 규칙이다.
- 수식과 코드가 많아 문장이 짧게 끊기는 것은 결함이 아니다.
- 실행 코드·토큰화 예시·테스트 데이터의 의도적인 띄어쓰기는 문장 교정 대상이 아니다.
