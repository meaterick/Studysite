# 채점 기준표

항목마다 0~20점이다. 먼저 아래 구간 가운데 레슨에 가장 가까운 것을 고르고, 구간 안에서 근거의 양과 심각도로 점수를 정한다. 같은 결함을 두 항목에서 두 번 감점하지 않는다. 예를 들어 틀린 수치는 정확성에서만 감점하고, 그 수치 때문에 예시가 쓸모없어졌다는 이유로 예시에서 다시 깎지 않는다.

구분(핵심·보충·심화)에 따라 기대 수준이 다르다. 심화 레슨은 선수 지식을 더 많이 가정해도 스캐폴딩 감점이 아니다(전문성 역전 효과, Kalyuga 외 2003). 대신 심화 레슨은 분석·평가 수준의 문항을 기대한다.

## 1. 정확성 (20)

정의·수식·수치·코드 동작·역사적 사실이 맞는가, 주장의 적용 범위가 정확한가, 본문·문항·실습·그림이 서로 맞는가.

| 점수 | 기준 |
| --- | --- |
| 20 | 오류가 없다. 일반화하는 문장에는 조건이 붙어 있다. 본문의 수치는 코드 출력·인용 자료로 확인된다. 용어가 사이트 표기와 일치한다. |
| 17~19 | 개념을 바꾸지 않는 사소한 문제만 있다: 한정어가 빠진 문장 하나, 출처 표기 형식, 출력과 반올림 자릿수가 다른 주석. |
| 13~16 | 국소 오류 1~2개: "항상"처럼 범위를 넘는 주장, 본문과 코드 수치의 불일치, 오래된 사실. 핵심 개념은 맞다. |
| 8~12 | 핵심 정의·공식·정답 번호에 오류가 있거나 국소 오류가 여럿이다. 학습자가 틀린 믿음을 갖게 된다. |
| 0~7 | 핵심 개념이 틀렸거나 본문끼리 모순된다. 코드가 실행되지 않는다. |

감점 예

- 확인 문제 정답 번호·해설 오류, 핵심 공식 오류: −6~−8
- 본문 수치와 실행 결과 불일치(`audit:comments`의 불일치, 결과 블록 불일치): −2~−4
- 적용 범위를 넘는 일반화("항상", "모든 경우", 조건 없는 등식): −1~−3
- 정의는 맞지만 용어가 사이트 표기와 다름(특징/특성, 우도/가능도): −1
- 인용 연도·저자 오류: −1~−2

확인 방법

- `audit:comments`의 불일치는 실제로 실행한 출력과 비교한 결과다. 출력이 맞고 주석이 틀렸는지, 주석이 설명인지 확인한다.
- `audit:content`의 과잉 일반화 후보는 문맥을 읽고 조건이 이미 앞뒤 문장에 있는지 본다.
- 확인 문제는 정답 선택지가 유일하게 옳은지, 오답 가운데 조건에 따라 옳을 수 있는 것이 없는지 본다.

## 2. 스캐폴딩 (20)

선수 지식을 불러오는가, 쉬운 것에서 어려운 것으로, 구체에서 추상으로 진행하는가, 풀이 예 → 안내된 연습 → 독립 연습으로 지원을 줄여 가는가, 한 번에 다루는 새 요소의 수가 감당할 만한가.

| 점수 | 기준 |
| --- | --- |
| 20 | 필요한 선수 지식을 `[[lesson:id]]`나 한 문장 복습으로 불러온다. 소제목마다 개념 하나를 다룬다. 단계표 → 코드 → 직접 해 보기 → 준비 실습 → 본 실습 순으로 지원이 줄어든다. 힌트가 단계적이다. 예상 시간이 상한 안이다. |
| 17~19 | 작은 빈틈 하나: 정의 전에 쓰인 용어 하나, 유도에서 빠진 한 단계, 본 실습이 요구하는 함수 하나가 본문에 없음. 한 문장으로 메울 수 있다. |
| 13~16 | 빈틈이 여럿이다. 유도가 건너뛴다. 예제에서 연습으로 넘어가는 다리가 없다. 한 절에 새 용어가 다섯 개 이상 몰린다. 또는 예상 시간이 상한을 넘는다. |
| 8~12 | 밝히지 않은 선수 지식을 널리 가정한다. 순서가 혼란스럽다. 연습이 가르치지 않은 기술을 요구한다. |
| 0~7 | 진행 순서가 없다. |

확인 방법

- 선수 개념(`concepts.ts`의 `requires`)을 다루는 레슨이 앞에 오는지는 `validate:content`가 이미 확인한다. 여기서는 본문이 그 지식을 **불러오는지** 본다.
- 본문이 뒤 레슨 문법·개념을 쓰면 "미리보기"라고 밝히고, 지금 이해할 범위와 실행만 할 범위를 나누었는지 본다.
- 요소 상호작용: 한 수식이나 코드 셀을 이해하려고 동시에 붙잡아야 하는 새 기호·용어의 수를 센다. 다섯 개를 넘으면 나누어 제시했는지 본다.
- 실습의 `prompt`가 요구하는 함수·문법이 본문이나 선수 레슨에 있는지 본다.

## 3. 예시 (20)

핵심 개념마다 작은 수로 손으로 따라갈 수 있는 풀이 예가 있는가, 같은 값을 코드로 다시 보이는가, 개념의 경계를 보이는 반례·대조 예가 있는가, 실제 AI 시스템의 사례와 연결되는가, 예가 최소한인가.

| 점수 | 기준 |
| --- | --- |
| 20 | 핵심 개념마다 풀이 예(단계표 또는 손계산)와 같은 값을 다시 계산하는 코드·결과 블록이 있다. 반례나 대조 예가 하나 이상 있다. 실제 쓰임과 연결된다. 예에 군더더기가 없다. |
| 17~19 | 핵심 개념 하나에 풀이 예나 반례가 없다. |
| 13~16 | 예는 있지만 한 종류(수식만, 코드만)이거나 가장 어려운 개념을 비켜 간다. 표면 특징이 같은 예만 있어 전이가 어렵다. |
| 8~12 | 예가 적고 설명이 대부분 추상적이다. |
| 0~7 | 예가 없다. |

확인 방법

- `audit:content`의 `코드·출력·표·그림` 열은 양만 보여 준다. 예가 **핵심 개념**을 다루는지 읽고 판단한다.
- 단계표는 입력과 중간값을 한 줄씩 적은 표다. 결론만 적은 표는 단계표가 아니다.
- 개념 수업에서 반례(non-example)는 정의의 경계를 정한다. 예: "행렬곱은 교환법칙이 성립하지 않는다"에는 $AB \ne BA$인 구체적 행렬이 있어야 한다.

## 4. 오개념 방지 (20)

이 주제의 흔한 오해를 예상하는가, 오해를 먼저 밝히고 반박하고 올바른 설명과 근거를 주는가(반박 텍스트), 학습자가 직접 계산할 수 있는 반례가 있는가, 확인 문제의 오답이 특정 오해를 진단하고 해설이 그 오해를 다루는가.

| 점수 | 기준 |
| --- | --- |
| 20 | [misconceptions.md](misconceptions.md)에서 이 주제의 주요 오해를 다룬다. 오해 → 반박 → 올바른 설명 → 근거(반례·실행 결과) 순서다. 오답 선택지가 오해와 대응하고 해설이 왜 틀렸는지 말한다. |
| 17~19 | 대부분 다룬다. 주요 오해 하나가 빠졌거나 주의 문구에 근거가 없다. |
| 13~16 | 주의 문구가 일반적이다("주의한다"). 목록의 주요 오해를 다루지 않는다. 오답이 대부분 무작위다. |
| 8~12 | 오해를 거의 다루지 않는다. 본문 표현이 오해를 부를 수 있다. |
| 0~7 | 본문이 오해를 강화한다. |

확인 방법

- `audit:content`의 `주의·표지·대조` 열: 주의 콜아웃 수, 오개념 표지 문구 수("흔한 실수", "혼동", "반례" …), "A가 아니라 B" 대조 문장 수.
- 문항 신호의 `오답 미해설`은 해설이 오답을 다루지 않는 문항이다. 오답이 흔한 오해를 담고 있는데 해설이 정답만 설명하면 감점한다. 오답이 명백히 무관하면 감점하지 않는다.
- 좋은 진단 문항(Wiliam, 2011; Haladyna 외, 2002): 오답마다 "이 선택지를 고른 학습자는 X라고 생각한다"고 말할 수 있다. "모두 옳다/해당 없음" 선택지와 부정형 질문("옳지 않은 것은")은 진단 정보를 줄인다.

## 5. 블룸 분류와 가독성 (20 = 10 + 10)

### 5a. 블룸 정렬 (10)

목표가 측정 가능한 동사로 인지 수준을 밝히는가, 평가 문항(확인 문제·출력 예측·실습·서술형)이 그 수준을 실제로 평가하는가(구성적 정렬, Biggs), 문항이 기억·이해에만 머물지 않는가, 문항에 답의 단서가 없는가.

| 점수 | 기준 |
| --- | --- |
| 10 | 목표 동사가 측정 가능하고 수준이 분명하다. 목표의 최고 수준을 평가하는 문항이 있다. 핵심 레슨은 적용 이상 문항이 있고, 심화 레슨은 분석·평가 문항이 있다. 정답 위치·길이에 편중이 없다. |
| 8~9 | 목표의 한 동사를 평가하는 문항이 없거나, 정답이 가장 긴 선택지인 문항이 절반을 넘는다. |
| 5~7 | 목표가 "이해한다"처럼 측정할 수 없거나, 문항 수준이 목표보다 두 단계 이상 낮다. |
| 0~4 | 목표와 문항이 다른 것을 다룬다. |

수준표와 동사 목록은 [bloom-ko.md](bloom-ko.md)에 있다.

### 5b. 가독성 (10)

| 점수 | 기준 |
| --- | --- |
| 10 | 문장이 짧고(평균 60자 이하, 120자 넘는 문장 드묾) 한 문장에 내용 하나다. 용어는 첫 사용 때 정의한다. 수식의 기호는 수식 바로 뒤에서 설명한다. 소제목이 내용을 말해 준다. 문체 규칙(한다체, 비유 없음)을 지킨다. |
| 8~9 | 긴 문장·긴 문단이 몇 개 있거나, 정의 없이 쓰인 용어 하나가 있다. |
| 5~7 | 긴 문장이 많고 번역투·명사 나열이 잦다. 용어 정의가 뒤로 밀린다. |
| 0~4 | 읽기 어렵다. |

기준과 예는 [readability-ko.md](readability-ko.md)에 있다.

## 총점과 등급

| 총점 | 등급 | 의미 |
| --- | --- | --- |
| 90~100 | 우수 | 경미 수정만 한다. |
| 80~89 | 양호 | 경미 수정으로 대부분 해결된다. |
| 70~79 | 보완 | 경미 수정 뒤에도 남는 결함이 있는지 보고, 있으면 중대 결함으로 올린다. |
| 0~69 | 재설계 검토 | 구조 변경 여부를 사용자에게 묻는다. |

한 항목이라도 10점 미만이면 총점과 관계없이 재설계 검토로 표시한다.

## 점수를 매길 때 피할 것

- 분량이 많다고 점수를 주지 않는다. 예시 항목은 핵심 개념을 다루는 예의 **적합성**을 본다.
- 신호가 0이라고 감점하지 않는다. 주의 콜아웃이 없어도 본문이 오해를 직접 반박하면 만점일 수 있다.
- 내용 자체가 어려운 것(내재 부하)을 설계 결함(외재 부하)으로 보지 않는다. 어려운 내용은 나누어 제시했는지를 본다.
- 학습 기록을 깨는 수정(키·정답 번호·선택지 순서 변경)을 경미 수정으로 처리하지 않는다.
