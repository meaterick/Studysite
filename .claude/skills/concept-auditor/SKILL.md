# 학습자료 개념 감사(concept-auditor)

이 스킬은 레슨이 **정확한 개념을, 학습자가 따라올 수 있는 순서로, 충분한 예와 함께, 흔한 오해를 막으며, 목표에 맞는 수준으로 읽기 쉽게** 가르치는지 판정한다. 점수는 수정의 우선순위를 정하는 도구다. 점수를 올리려고 내용을 늘리지 않는다.

기준은 교수설계 연구(개정 블룸 분류, 인지부하 이론, Merrill의 교수 원리, 스캐폴딩과 근접발달영역, 반박 텍스트, 진단 문항 설계)와 이 저장소의 [편집 안내](../../../docs/contributing/content-authoring.md)를 합쳐 만들었다. 출처와 라이선스는 [references/sources.md](references/sources.md)에 있다.

## 범위

| 대상 | 파일 | 기본 포함 |
| --- | --- | --- |
| 레슨 | `src/content/modules/<모듈>/<레슨 id>.ts`(목표·쓰이는 곳·본문·확인 문제·출력 예측·서술형·참고 자료) | 예 |
| 레슨 실습 | `src/content/modules/<모듈>/labs/<레슨 id>.ts`(문제 설명·힌트) | 예(문제 설명과 힌트만) |
| 모듈 | `src/content/modules/<모듈>/index.ts`(목표 문제·학습 목표·백지 복습) | 모듈 단위로 검토할 때 |
| 과제 | `src/content/modules/<모듈>/assignment.ts` | 요청할 때만 |

`docs/curriculum/`은 생성 문서이므로 고치지 않는다. 원본을 고친 뒤 `npm run docs:generate`로 다시 만든다.

## 준비

```bash
npm ci
python3.12 -m venv .venv && .venv/bin/pip install -r scripts/content/requirements.txt
```

matplotlib 3.8.4는 Python 3.13용 휠이 없으므로 3.12 가상환경을 쓴다. 이후 `PYTHON=.venv/bin/python`을 붙여 Python 검사를 실행한다.

## 작업 순서

### 1. 범위와 기준 상태

요청에서 대상(전체·모듈 slug·레슨 id)을 정한다. 수정 전 상태를 기록한다.

```bash
npm run validate:content
PYTHON=.venv/bin/python npm run check:labs -- <모듈 slug>
```

### 2. 자동 신호 수집

```bash
npm run audit:content -- <모듈 slug | 레슨 id ...> --detail --json /tmp/signals.json
PYTHON=.venv/bin/python npm run audit:comments -- <모듈 slug | 레슨 id ...>
```

- `audit:content`(`scripts/content/audit.ts`): 목표 동사의 블룸 수준, 평가 문항의 수준 분포, 정답 위치·길이 편중, 부정형 질문, 오답 해설 여부, 주의 콜아웃·오개념 표지, 과잉 일반화 표현, 문장·문단 길이, 번역투, 높임체, 예상 시간을 계산한다.
- `audit:comments`(`scripts/content/audit-comments.ts`): 코드 셀의 `print(...)  # 값` 주석을 실제 출력과 비교한다. 불일치는 정확성 감점 후보다.

신호는 휴리스틱이다. 신호만 보고 감점하지 않고, 반드시 해당 문장을 읽고 판단한다. 신호가 없어도 결함이 있을 수 있다.

### 3. 읽기

레슨마다 다음을 읽는다.

1. 레슨 원본 전체와 실습 파일의 문제 설명·힌트
2. 선수 지식: `concepts`의 선수 개념(`src/content/curriculum/concepts.ts`)을 다루는 레슨의 목표, `requires`로 적은 레슨, 같은 모듈의 앞 레슨
3. 본문이 `[[lesson:id]]`로 가리키는 레슨의 제목과 목표(참조가 맞는 대상을 가리키는지)
4. 주제에 해당하는 오개념 목록([references/misconceptions.md](references/misconceptions.md))

수치·코드 동작·역사적 사실은 기억에 의존하지 않는다. 코드는 실행해 보고, 사실은 참고 자료나 원 논문으로 확인한다. 확인하지 못한 주장은 "확인 필요"로 적고 감점하지 않는다.

### 4. 채점

[references/rubric.md](references/rubric.md)의 기준표로 항목마다 0~20점을 준다. 항목마다 근거를 `파일:줄` 한 줄로 남긴다.

| 항목 | 묻는 것 | 주요 근거 |
| --- | --- | --- |
| 정확성 | 정의·수식·수치·코드 동작·사실이 맞고, 주장의 적용 범위가 정확한가 | 본문 대조, `audit:comments`, `check:labs`, 과잉 일반화 후보 |
| 스캐폴딩 | 선수 지식을 불러오고, 쉬운 것에서 어려운 것으로, 예제 → 안내된 연습 → 독립 연습으로 넘어가는가 | 선수 개념, 소제목 구성, 준비 실습, 힌트, 예상 시간 |
| 예시 | 핵심 개념마다 작은 수로 따라갈 수 있는 풀이 예와 경계를 보이는 반례·대조 예가 있는가 | 코드·결과 블록, 단계표, 그림, 직접 해 보기 |
| 오개념 방지 | 이 주제의 흔한 오해를 예상하고 반박하며, 오답 선택지가 특정 오해를 진단하고 해설이 그 오해를 다루는가 | 주의 콜아웃, 대조 문장, 오개념 목록, 문항 해설 |
| 블룸·가독성 | 목표가 측정 가능한 동사로 수준을 밝히고 문항이 그 수준을 평가하는가(10점) + 문장이 짧고 용어가 첫 사용 때 정의되는가(10점) | 블룸 분포, 문항 편중, 문장 길이, 번역투 |

등급: **우수** 90점 이상 · **양호** 80~89 · **보완** 70~79 · **재설계 검토** 70 미만. 한 항목이라도 10점 미만이면 총점과 관계없이 재설계 검토로 표시한다.

### 5. 결함 분류: 경미 또는 중대

결함마다 "고치는 데 무엇이 바뀌는가"로 판정한다. 점수가 낮다고 중대 결함이 되는 것이 아니다.

| 경미 — 바로 고친다 | 중대 — 묻고 승인 후 고친다 |
| --- | --- |
| 오탈자, 띄어쓰기, 조사, 문장 부호 | 레슨의 소제목 순서 재배치, 레슨 분할·병합 |
| 같은 뜻을 더 분명하게 다듬기, 긴 문장 나누기 | 선수 개념을 설명하는 새 절이나 새 레슨 추가, 레슨을 다른 모듈로 이동 |
| 적용 범위 한정어 추가("정수 $b \ne 0$에 대해") | 난이도·대상 학습자·구분(핵심↔보충↔심화) 변경 |
| 검증 가능한 국소 사실 오류 수정(값·연도·저자) | 모듈 구조, 개념(`concepts`)·선수(`requires`) 연결 변경 |
| 짧은 예시 추가(문장 몇 개, 작은 단계표, 결과 블록이 있는 짧은 코드 셀) | 문항·실습의 수·`key`·채점 의미 변경, 과제 채점 기준 변경 |
| 짧은 오개념 주의 콜아웃(`:::warn`, 세 문장 이내) | 정답 번호나 선택지 순서 변경(저장된 응답 기록이 선택지 번호를 가리킨다) |
| 첫 사용 용어 정의 한 문장, `[[lesson:id]]` 선수 참조 추가 | 여러 레슨·모듈에 걸친 일괄 변경, 사이트 전체 표기 방침 변경 |
| 확인 문제 해설에 오답이 왜 틀렸는지 한 문장 추가 | 고치면 핵심 레슨이 예상 시간 상한을 넘는 경우 |
| 정답 의미를 바꾸지 않는 선택지 문구 다듬기 | 내용 삭제, 사실관계가 학계에서도 갈리는 문제의 방침 결정 |

경미 수정이라도 코드나 수치를 바꾸면 실행해서 확인한다. 정답 번호가 틀린 것을 발견하면 오류 수정이므로 고치되, 보고서에 따로 적는다.

### 6. 보고와 수정 순서

1. **전체 점수표를 먼저 출력한다.** 형식은 아래 "출력 형식"을 따른다.
2. **경미 수정을 바로 파일에 반영한다.** 레슨 하나씩 고치고, 고친 내용을 `파일:줄 — 전 → 후`로 기록한다.
3. **검증한다.**
   ```bash
   npm run validate:content
   PYTHON=.venv/bin/python npm run check:labs -- <고친 모듈>
   PYTHON=.venv/bin/python npm run audit:comments -- <고친 모듈>
   npm run docs:generate && npm run docs:check
   npm run lint
   ```
   실패하면 고친 뒤 다시 실행한다. 실패를 남긴 채 끝내지 않는다.
4. **중대 결함은 고치지 않고 묻는다.** 결함마다 문제·근거·영향 범위와 선택지 2~4개(장단점, 추천안을 첫째로)를 정리하고 `AskUserQuestion`으로 묻는다. 한 번에 4개까지 묻고, 비슷한 결함은 하나의 질문으로 묶는다. 승인받은 안만 반영하고, 반영 뒤 3단계 검증을 다시 한다.
5. **기록한다.** `docs/development/concept-audit-<날짜>.md`에 점수표·수정 내역·결정 사항을 남기고 [문서 홈](../../../docs/README.md)의 개발 문서 목록에 연결한다.

## 수정 규칙(이 저장소)

- 레슨 `id`, 모듈 `slug`, 문항·실습 `key`, 과제 `key`, 과제 셀 `id`는 바꾸지 않는다. 학습 기록이 이 값에 연결된다.
- 본문·해설·서술형 모범답안은 한다체, 실습 문제·힌트·과제 안내는 합니다체로 쓴다.
- 비유·은유·의인화를 쓰지 않는다. 정의, 수식, 계산 예, 실제 사례로 설명한다.
- 다른 레슨은 `[[lesson:id]]`로 가리킨다. "N주차" 같은 일정 표현은 쓰지 않는다.
- 본문에 적는 수치는 그 레슨의 코드 셀이나 실습에서 실제로 나오는 값이어야 한다. 새 코드 셀에는 결과 블록(` ```output `)을 붙이고 `check:labs`로 확인한다. 브라우저(Pyodide, wasm32)와 CPython에서 다른 출력(NumPy 기본 정수형, 메모리, 시간, 주소)은 결과 블록에 쓰지 않는다.
- 용어는 편집 안내의 표기를 따른다(학습 데이터, 특성, 규제, 정규화, 기준 모델, 가능도 …).
- `md`·`py` 템플릿 안의 LaTeX는 백슬래시 하나, 일반 문자열(문항·해설·힌트)은 두 개로 쓴다. 템플릿 안 백틱은 `` \` ``로 쓴다.
- 핵심 레슨의 예상 시간 상한(기본 45분, Python 75분, 수학·데이터·머신러닝·딥러닝 60분)을 넘기지 않는다. 내용을 더하면 `validate:content`의 경고를 확인한다.

## 출력 형식

### 점수표

모듈마다 표 하나, 마지막에 전체 요약을 둔다.

```markdown
| 레슨 | 구분 | 정확 | 스캐폴딩 | 예시 | 오개념 | 블룸·가독 | 총점 | 등급 | 조치 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | --- | --- |
| matrix-multiplication | 핵심 | 20 | 19 | 20 | 19 | 18 | 96 | 우수 | 경미 1 |
```

`조치`에는 `없음`, `경미 N`, `중대 #번호`를 적는다. 표 아래에 감점 근거를 레슨당 한두 줄로 적는다.

### 경미 수정 기록

```markdown
- `src/content/modules/<모듈>/<레슨>.ts:<줄>` [항목] 전: "…" → 후: "…" (이유)
```

### 중대 결함 카드

```markdown
#### 중대 #N <제목>
- 대상: 레슨·모듈, 영향 범위(학습 기록·시간·다른 레슨)
- 문제와 근거: 무엇이 왜 학습을 방해하는가(파일:줄, 신호 수치)
- 선택지: A(추천) … / B … / C 현행 유지 …
```
