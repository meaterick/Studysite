# 학습 콘텐츠 교육 설계 검토 — 초심자·최상위권 학습자 관점

> 검토 범위: `src/content/weeks/week1.ts` ~ `week8.ts`, `src/content/syllabus.ts`의 학습목표·본문·실행형 코드 셀·퀴즈·백지공부 시트·주간 과제·캡스톤 루브릭.
>
> 판정 기준: 처음 AI를 체계적으로 배우는 학습자가 **설명할 수 있고**, **재현 가능한 실험을 수행하며**, **실패를 해석해 다음 실험을 설계할 수 있는가**.

## 총평

이 콘텐츠는 보통의 입문 강의보다 훨씬 강하다. 각 주차가 “왜 필요한가 → 수식/직관 → 작은 직접 구현 → 라이브러리/실전 적용 → 퀴즈·백지공부·과제”로 이어지고, 특히 W3의 자동미분+gradient check, W4의 ablation, W7의 골든셋 기반 RAG 평가는 세계 상위권 CS/AI 과목의 좋은 습관을 실제 산출물로 바꾼 설계다. 시각 자료와 실행형 코드 셀도 개념의 추상도를 낮춘다.

다만 현재 8주 과정은 **‘첫 AI 강의’와 ‘압축된 고급 개론’이 한 주 안에서 충돌**한다. W1은 Python·Git·선형대수·확률·정보이론·최적화를 함께 다루고, W2는 전처리부터 10개가 넘는 알고리즘과 검증까지 폭이 넓다. W4에는 CNN 외에 생성모델까지, W6에는 학습·스케일링·정렬·강화학습·디코딩을 함께 넣는다. 설명의 질이 높아도 초심자는 앞 개념을 회수·적용할 시간보다 새 용어를 통과하는 시간이 길어질 수 있다.

**권고 결론:** 내용 수준을 낮추지 말고, 필수 경로를 좁히고(핵심 3~5개), 나머지를 “선택 심화”로 명시하라. 모든 주에 사전 진단·완료 기준·실패 해석을 추가하면 입문자 친화성과 학술적 엄밀성을 동시에 높일 수 있다.

## 커리큘럼 흐름 평가와 권장 재배치

현재 큰 흐름인 수학·ML → 신경망 → 비전 → Transformer → LLM → RAG/에이전트 → 책임/캡스톤은 자연스럽고, W7 과제를 W8 캡스톤으로 확장하도록 연결한 점도 좋다. 다음처럼 “핵심선”을 명시하는 편이 더 효과적이다.

1. **0주차(필수, 2~3시간 비동기)** — Colab 실행, Python 최소 문법, NumPy 배열/shape, Git 제출 흐름, 진단 퀴즈. 부족한 학습자는 보충 경로로, 경험자는 면제 경로로 보낸다.
2. **W1 핵심** — 벡터·내적, 확률의 언어, 손실·gradient descent, 선형회귀 미니랩. 고유값/SVD, MLE/MAP, KL/엔트로피의 상세 유도는 ‘읽기 심화’로 옮긴다.
3. **W2 핵심** — train/validation/test, 누수, baseline, 회귀/로지스틱 회귀, 지표·오차 분석. KNN·NB·트리·앙상블·SVM·K-Means·PCA는 알고리즘 선택 지도와 선택 랩으로 묶는다.
4. **W3** — 유지 권장. 계산 그래프 → 역전파 → gradient check → PyTorch 전환은 탁월한 계단식 설계다.
5. **W4** — CNN·전이학습·진단을 필수로 유지하되 VAE/GAN/Diffusion은 “생성모델 맛보기” 선택 모듈로 분리한다.
6. **W5** — RNN의 역사적 맥락은 짧게 두고 Self-Attention, mask, shape, Transformer block에 시간을 집중한다.
7. **W6** — “LLM 학습/정렬”과 “디코딩·서빙”을 두 개의 명시적 트랙으로 나눈다. 강화학습의 수식적 깊이는 선택 심화로 둔다.
8. **W7~W8** — RAG 평가·안전·캡스톤 연결은 유지한다. W8의 거버넌스는 마지막 주가 아니라 W7 RAG/에이전트의 prompt injection·권한 설계 바로 뒤에서도 짧게 회수한다.

## 주차별 피드백

### W1 — 가장 큰 병목, 반드시 축소

**좋은 점:** AI 지형도로 동기를 만들고 Python 사전, 코사인 유사도, 경사하강법, 손실 기반 선형회귀로 실제 학습의 핵을 연결한다. ‘처음 어려운 것은 정상’이라는 문장도 학습 불안을 낮춘다.

**문제:** Python·Git·NumPy/Pandas/Matplotlib, 선형대수(기저/rank/고유값/SVD), 확률·베이즈·MLE/MAP·정규분포, 정보이론, 미분·GD를 같은 필수 주차에 둔다. 학습목표 7개와 키워드 13개는 첫 주의 작업기억 한계를 넘기기 쉽다.

**개선:** 첫 화면에 “이번 주에 반드시 남길 것: (1) 벡터 내적, (2) 손실, (3) gradient descent, (4) Colab 실행”을 제시한다. W1 과제의 베이즈 재계산은 좋은 통합 과제지만 선형회귀 과제와 분리해 선택/보충으로 둔다. 또한 모든 코드 셀에 `shape`, 예상 출력, 한 줄 수정 과제를 붙인다. 예: `learning_rate=0.1`을 바꿔 loss가 발산하는 경계와 이유를 기록한다.

### W2 — 훌륭한 실무 감각, 핵심 알고리즘 수를 줄일 것

누수 실험, baseline, CV, 지표 선택, 오차 분석을 과제에 넣은 것은 매우 좋다. 다만 초심자에게 한 주에 전처리+회귀+분류+KNN/NB/트리/앙상블/SVM/K-Means/PCA+편향-분산+검증+지표는 ‘모델 이름 암기’로 변할 위험이 있다.

필수 과제를 **로지스틱 회귀 vs 랜덤포레스트 2개**와 baseline으로 고정하고, 나머지는 ‘언제 쓰는가’ 비교표+선택 실험으로 옮긴다. breast_cancer 데이터만 써도 좋지만, 목적 변수에서 파생된 누수 특징은 초심자에게 지나치게 인위적으로 보일 수 있으므로 날짜·개체 중복·전처리 fit 위치를 포함한 현실적 누수 사례도 하나 추가한다.

### W3 — 핵심 실습의 모범, 준비용 scaffold 보강

Value 클래스 확장, gradient check, make_moons, PyTorch 비교는 매우 적절한 순서다. 다만 처음부터 클래스/연산자 오버로딩을 읽는 부담이 크다. 시작 코드(scaffold), 단계별 테스트 3개(덧셈, 곱셈, 작은 그래프), 실패 메시지 표를 제공한다. 90% 정확도는 데이터 split·seed·epoch·hidden width를 고정하지 않으면 공정한 완료 기준이 아니다. ‘권장 설정에서 ≥90%’와 ‘그렇지 않으면 확인할 4항목’을 명시한다.

### W4 — 실험 설계는 우수, 컴퓨팅 예산을 현실화

CIFAR-10 ablation과 전이학습, 오분류 분석은 강력하다. 하지만 10 epoch 기본선 + 4개 ablation + 전이학습 2조건은 Colab 시간·GPU 가용성에 민감하다. 필수는 **기본선+ablation 2개+오류 분석**으로 줄이고, 전이학습/4개 ablation은 팀 또는 선택 심화로 한다. 데이터 augmentation은 반드시 train에만 적용된다는 점, validation/test에는 적용하지 않는다는 점을 체크리스트화한다.

### W5 — 역사보다 계산을 우선

RNN→LSTM/GRU→Seq2Seq→Attention→Transformer의 문제 해결 서사는 좋고, 손계산 Self-Attention과 shape 추적은 필수로 유지할 가치가 크다. 반면 멀티헤드 attention+Wo+2층 문자 LM+논문 현대화 조사까지는 한 주의 산출물로 무겁다. 최소 경로는 단일 헤드 causal attention의 정답 검증 → 멀티헤드 확장 → PyTorch allclose로 만들고, 문자 LM과 RoPE/GQA 조사는 선택으로 둔다. 마스크를 빼도 ‘출력 차이’만 보지 말고 **미래 토큰을 바꿨을 때 이전 위치 출력도 바뀌는가**라는 인과성 테스트를 추가한다.

### W6 — 용어와 과제의 범위를 정돈

BERT/GPT/T5 비교, scaling, SFT/RLHF/DPO, decoding, latency/throughput, hallucination은 모두 중요하지만 입문 한 주의 필수 범위로는 넓다. 필수 질문을 “LLM은 다음 토큰 예측으로 무엇을 배울 수 있고 무엇을 보장하지 않는가?”로 고정하고, 학습/정렬과 추론/디코딩을 분리 표시한다. 환각 과제는 외부 모델·시점·프롬프트·출력 전문·검증 출처를 반드시 기록하는 실험 템플릿을 제공해야 재현 가능하다. ‘품질 1~5’에는 길이, 정확성, 지시 준수 등 루브릭 앵커를 제공한다.

### W7 — 가장 실전적인 주차, 보안 평가를 필수 완료 조건으로

RAG를 TF-IDF로 먼저 작동시키고 실제 임베딩은 Colab 확장으로 안내한 것은 환경 제약을 정직하게 다룬 좋은 선택이다. 골든셋 20문항, Recall@k/MRR, ‘자료에 없음’ 측정, 사용자 피드백 전후 비교도 훌륭하다.

추가할 핵심 실습은 세 가지다: (1) **인용 단위 정확성**(답의 각 핵심 주장에 근거 청크가 실제로 있는가), (2) **문서 내 prompt injection**에 대한 신뢰 경계, (3) **권한 있는 도구 호출의 승인 단계**. 또한 TF-IDF 결과를 “의미 임베딩과 동등”하게 오해하지 않도록, 동의어 질의·고유명사 질의 각각에서 Dense/Sparse의 실패 사례를 한 쌍씩 실험하게 한다.

### W8 — 좋은 마무리, 캡스톤 시작 시점을 앞당길 것

모델카드, 실패 사례, 재현성, 발표 루브릭이 모두 구체적이다. 다만 캡스톤을 W8에 처음 본격 착수하면 문제 정의·데이터 수집·평가셋 설계 시간이 부족하다. W5에 관심 분야/팀/문제 초안, W6에 데이터와 baseline, W7에 평가·위험 레지스터를 제출하는 **3단계 milestone**을 추가한다. 모델카드는 제출 직전 문서가 아니라 프로젝트 시작부터 업데이트하는 살아 있는 문서로 다룬다.

## 모든 실습에 적용할 표준 템플릿

각 실행형 실습은 아래 순서로 통일한다.

1. **질문:** 무엇을 확인하는 실험인가?
2. **예측:** 실행 전 결과를 한 문장으로 쓴다.
3. **최소 코드:** 바꿔도 되는 변수는 1~2개로 제한한다.
4. **통과 조건:** 숫자/그래프/불변식으로 명시한다. 예: `relative_error < 1e-5`, held-out Recall@3 ≥ 기준선.
5. **반례:** 변수 하나를 바꿔 예상이 깨지는 경우를 관찰한다.
6. **해석:** 결과가 맞아도 틀려도 다음에 확인할 원인을 2~3개 제시한다.
7. **기록:** seed, 데이터 버전, 라이브러리 버전, 실행 시간, 한계를 남긴다.

이 구조는 “코드를 따라 친다”에서 “가설을 세우고 증거로 판단한다”로 학습을 이동시킨다.

## 추가 권장 실습 (우선 도입 순)

1. **W0 환경·shape 진단 랩:** Colab, 배열 shape, seed, plot, Git 제출을 30분 안에 성공시키는 체크포인트.
2. **W2 데이터 카드 + 누수 탐정:** 데이터 행의 의미, 수집 시점, 대상/특징 경계를 문서화하고 누수를 직접 찾아낸다.
3. **W3 불변식 기반 디버깅:** gradient check 외에 작은 입력에서의 shape, finite value, loss 감소를 자동 테스트한다.
4. **W4 오류 예산 랩:** 데이터/모델/최적화/평가 중 어느 축이 병목인지 가설표를 채운다.
5. **W5 causal test:** 미래 토큰 변경이 과거 위치 출력에 영향을 주지 않는지 자동 검증한다.
6. **W6 모델 행동 로그:** 생성 설정·모델 버전·프롬프트·출력·사실 검증을 하나의 표에 기록한다.
7. **W7 RAG red-team:** 인용 누락, 자료 외 질문, 상충 문서, prompt injection, 권한 없는 도구 사용을 포함한 최소 10개 안전 테스트.
8. **W8 재현성 smoke test:** 다른 사람이 새 환경에서 README 한 장만 보고 실행해 baseline 결과를 재현한다.

## 측정과 운영 제안

- 주차 시작 전 3문항 **사전 진단**, 끝에 동일 핵심 개념의 3문항 **사후 진단**을 둔다. 점수는 평가보다 보충 경로 선택에 쓴다.
- 퀴즈는 현재처럼 깊지만 문항 수가 많다. 필수 5문항(회수용) + 도전 5~20문항(토론용)으로 구분한다.
- 과제 루브릭에 “완벽한 성능”보다 **실험 로그, 실패 분석, 재현성**의 배점을 유지한다. 이는 이미 W4/W7/W8에서 잘 구현되어 있다.
- 각 주의 첫 문단에 ‘선수지식’, ‘필수 산출물’, ‘예상 소요시간(핵심/심화)’을 표시한다.
- 정규 세션에서는 새 내용을 더 설명하기보다, 사전 진단에서 드러난 오개념과 서로 다른 실험 결과를 비교·토론한다.

## 도입 순서

1. W1 축소와 W0 진단 랩을 먼저 도입한다.
2. 모든 코드 셀에 예상 결과·통과 조건·디버깅 경로를 추가한다.
3. W2/W4/W6의 필수·선택 경계를 나눈다.
4. W7의 RAG 안전·인용 평가와 W5부터 시작하는 캡스톤 milestone을 추가한다.
5. 한 기수 운영 뒤 사전/사후 진단, 과제 완주율, 재제출 사유, 실습 실패 로그를 바탕으로 난이도를 조정한다.

이 과정은 이미 높은 콘텐츠의 깊이를 깎는 작업이 아니다. 초심자가 같은 높은 기준에 실제로 도달하도록, **필수 경로의 폭을 좁히고 피드백 고리를 촘촘히 만드는 작업**이다.
