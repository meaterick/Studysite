# 보안 점검 및 운영자 보안 기록

> 과거 검토 기록입니다. 당시 관측·제안과 현재 구현은 다를 수 있습니다. 현재 구조는 [기술 구조](../../development/architecture.md), 학습 범위는 [전체 커리큘럼](../../curriculum/README.md), 운영 절차는 [문서 홈](../../README.md)에서 확인합니다.

점검일: 2026-10-19. 기준: main `6550f06`의 소스, 잠금 파일, nginx·PM2·배포 설정.
실제 OCI 호스트, 운영 데이터, 계정·SSH 기록에는 접근하지 않았다. 운영 사이트에 공격 트래픽을 발생시키지 않았다.

## 수정 사항

| 항목 | 확인한 위험 | 적용한 조치 |
| --- | --- | --- |
| 세션·OAuth 서명 키 | 운영에서도 미설정 시 공개된 개발용 키를 사용해 세션 위조 가능 | 운영 32자 이상·기본값 금지, 공유 키 검증, 배포·시작 단계 차단 |
| 최초 가입자 권한 | 공개 배포 직후 방문자가 관리자가 될 수 있음 | 운영 신규 관리자는 ADMIN_EMAILS 명시 필요. 기존 권한 유지 |
| 공개 출처 | PUBLIC_ORIGIN 누락·오타 시 요청 헤더로 리다이렉트 출처 결정 | 운영 HTTPS 출처 필수. Host/Forwarded 헤더에 의존하지 않음 |
| 외부 출처 변경 요청 | 일반 POST 로그아웃에는 Server Action의 자동 출처 검사가 적용되지 않음 | Proxy 출처 검사, 로그아웃 핸들러 Origin 재검사·303 응답 |
| 보안 가시성 | 서버 예외만 저장해 인증 실패·권한 거부·요청 제한 추적 어려움 | 전용 이벤트, 관리자 화면, 기간·종류·위험도·IP 필터와 대응 설명 |
| nginx 차단 기록 | 앱 앞에서 거절한 429·413 등은 앱이 알 수 없음 | query-free JSON 로그, 읽기 전용 최근 기록, 회전·권한 자동 설정 |
| 프록시 IP | 클라이언트 X-Forwarded-For를 이어붙임 | nginx에서 remote_addr로 덮어쓰기. 명시적으로 신뢰한 X-Real-IP만 사용 |
| 채팅 스트림 | 멤버의 관리자용 쿼리가 자기 대화로 처리돼 오용 구별 어려움 | inbox·다른 계정 요청은 403 및 감사 이벤트 |
| OAuth 요청 | 상위 서비스 지연 시 연결이 오래 유지될 수 있음 | 토큰·프로필 요청 각각 10초 제한 |
| 의존성 | DOMPurify·sharp·source-map-js 취약 버전 | DOMPurify 3.4.17, sharp 0.35.5, source-map-js 1.2.2 및 잠금 파일 갱신 |

페이지·서버 액션의 requireAdmin/requireUser와 API의 DB 권한 재검사를 유지했다.
오래된 admin 역할 쿠키가 있어도 DB에서 member이면 백업을 허용하지 않는다.
첨부 다운로드는 제출 소유자·관리자만 허용하며 attachment·nosniff·no-store를 유지한다.

## 기록과 운영

- 로그인 성공·실패, 유효하지 않은 세션, 로그인 없는 보호 API 접근, 권한 거부, 계정 요청 제한,
  민감 경로 탐색, 외부 출처 요청 차단, 운영자 백업 다운로드를 기록한다.
- 상태 값은 실제 응답이나 차단 원인을 나타낸다. Proxy 권한 거부는 리다이렉트(307)로 표시한다.
  계정 요청 제한은 `/actions/<종류>`로 기록하며 IP가 없을 수 있다.
- 같은 종류·IP·계정·메서드·경로·상태를 5분 단위로 묶는다. 최대 30일·10,000개 묶음이다.
  서버 시작·새 이벤트·조회 및 매시간 정리한다. 24시간 통계는 보관 중인 묶음의 마지막 발생 시각 기준이다.
- nginx는 4xx·5xx만 기록한다. 현재 파일 마지막 512KB의 최근 100건이며 약 5초 내 반영한다.
  앱 이벤트와 중복될 수 있어 합산하지 않는다. 파일 회전 후 지난 파일은 화면에서 읽지 않는다.
- nginx 로그는 매시간 검사해 일별 또는 10MB 초과 시 회전하며 이전 파일 7개를 보관한다.
  검사 간 폭증하면 10MB를 넘을 수 있다. root 소유·앱 그룹 읽기(640), 디렉터리 750이다.
- 쿼리·본문·쿠키·OAuth 코드·이메일·User-Agent를 보안 로그에 저장하지 않는다.
  IP·계정 ID·경로는 관리자만 열람한다. 탈퇴와 별개로 보안 기록은 상한까지 남는다.
  DB 백업 안의 기록은 기존 백업 회전 정책에 따라 삭제된다. 개인정보처리방침도 갱신했다.
- TRUST_PROXY=1은 loopback 바인딩·nginx 헤더 덮어쓰기를 전제로 한다. CDN이나 프록시를 추가하면
  원 IP 복원·신뢰 범위를 따로 구성해야 한다. 현재는 직접 연결한 프록시 IP가 표시될 수 있다.
- 기록은 공격 의심 신호다. 취소·만료·정상 404·공유 NAT 요청도 포함되며 공격 성공을 입증하지 않는다.
- OCI 방화벽 차단 패킷·포트 스캔·SSH는 VCN Flow Logs와 호스트 인증 로그에서 별도 확인한다.
  배포 이전 요청은 소급 수집되지 않는다.

## 검증

- `npm run test:security`: 약한 키·출처 차단, 세션 변조, 최초 가입자·관리자 지정, IP 신뢰,
  탐색·외부 요청 차단, DB 기준 API·제출물 접근 통제, 집계·쿼리 제거·검색, 저장 상한, nginx 로그 처리.
- `npm run lint`, `npm run build`, 콘텐츠 검증(오류·경고 0), `git diff --check`, 배포 shell 구문 검사.
- standalone HTTP 검사: 관리자 화면·필터·nginx 기록 렌더링, 미인증·멤버 차단, 쿼리 제거,
  민감 경로 차단, 외부 로그아웃 차단·정상 로그아웃 303.
- 생성한 HTTP/HTTPS nginx 설정을 nginx 1.24.0 `-t`로 검사했다(테스트 환경 포트·임시 경로 적용).
  브라우저 바이너리 다운로드가 차단되어 실제 브라우저의 시각적 검증은 수행하지 못했다.
- pull request에 보안 회귀·lint·콘텐츠·프로덕션 빌드·운영 의존성 audit 검사를 추가했다.
- `npm audit --omit=dev`: 알려진 취약점 0개(점검 시점 기준).
- 전체 audit에는 개발용 ESLint 경로의 braces 3.0.3 및 전이 패키지 경고 5개가 남는다.
  프로덕션 의존 경로에는 없다. 사용자 입력을 lint/glob 패턴으로 전달하지 않는다.
  공식 패치가 없어 프레임워크 다운그레이드나 비공식 패키지 대체를 적용하지 않았다.

## 남은 확인 사항

1. 기본값·약한 SESSION_SECRET을 사용했다면 새 무작위 키로 교체해 기존 세션을 무효화해야 한다.
   Actions 비밀 값은 읽지 않았다. 새 배포는 잘못된 설정을 거부한다.
2. 이미 만들어진 관리자는 자동 강등하지 않는다. 운영자가 신원을 확인해야 한다.
   이후 신규 가입자만 명시한 관리자 목록으로 제한한다.
3. 실제 OS·nginx·OpenSSH 버전, OCI 보안 목록·NSG·Flow Logs·SSH 설정은 코드만으로 확인할 수 없다.
4. CSP의 기존 unsafe-inline은 유지했다. nonce 전환은 별도 성능·렌더링 검토가 필요하다.
5. 개발용 braces는 공식 패치 출시 후 갱신해야 한다.
