# 사이트와 학습 흐름

[문서 홈](../README.md) · 경로와 코드 표기는 저장소 루트 기준입니다.

## 과정의 구조

학습자는 **분야 → 모듈 → 레슨** 순으로 탐색합니다. 코드의 트랙은 80개 개념의 여섯 분류(프로그래밍, 수학, 데이터, 머신러닝, 딥러닝, 생성형 AI)에 과정 개요(0)·캡스톤(7)·확장(X)을 더한 것이고(`src/content/curriculum/tracks.ts`), 모듈은 목표 문제 하나를 중심으로 레슨과 백지 복습, 과제를 묶습니다(`src/content/modules/<slug>/`). 레슨은 개념 하나를 다루며 핵심·보충·심화로 나뉩니다(`src/content/tiers.ts`).

- **핵심 레슨**: 필수 경로입니다. 80개 개념은 모두 핵심 레슨에서 다룹니다. 모듈의 핵심 레슨을 모두 마치면 모듈이 완료됩니다.
- **보충 레슨**: 핵심을 실무 도구나 다른 방법으로 넓히는 선택 레슨입니다. 기록만 남습니다.
- **심화 레슨**: 유도, 통계적 가정, 계산 효율을 다루는 선택 레슨입니다. 모듈의 심화 레슨·심화 실습·과제 심화 문제를 모두 마치면 그 모듈의 **심화 달성**이 표시됩니다(`src/lib/achievement.ts`).
- **확장 모듈**(X-1 책임 있는 AI, X-2 비전과 생성 모델)은 완료 조건이 없습니다.

전체 분야를 차례로 공부할 때 참고하는 추천 일정은 16주이며(`src/content/curriculum/schedule.ts`), 기수 시작일을 정하면 진도 화면과 운영자 대시보드가 이번 주 범위와 캡스톤 준비 단계를 보여 줍니다. 레슨 사이의 선수관계는 개념의 선수관계(`src/content/curriculum/concepts.ts`)에서 계산합니다.

## 학습자 화면

| 경로 | 내용 |
| --- | --- |
| `/` | 학습 방법과 분야 소개. 헤더의 Aegis 로고로 돌아옵니다 |
| `/curriculum` | 학습 분야 카드와 주요 주제 |
| `/curriculum/details` | 전체 모듈과 레슨, 분야별 학습 목표, 개념의 선수관계, 추천 일정 |
| `/tracks/[track]` | 분야의 주요 주제와 모듈·레슨 목록 |
| `/modules/[module]` | 모듈 개요: 목표 문제, 학습 목표, 핵심·보충·심화 레슨 목록과 진행 상태, 진단 평가·백지 복습·과제·복습 노트로 가는 길 |
| `/modules/[module]/lessons/[lesson]` | 레슨 본문, 실행 예제, 선수·후속 레슨, 실습 바로가기 |
| `/modules/[module]/practice/[lesson]` | 준비 점검, 코딩테스트, 출력 예측, 확인 문제, 서술형, 레슨 완료, 모듈 백지복습 링크 |
| `/modules/[module]/diagnostic` | 진단 평가: 핵심 레슨의 확인 문제를 레슨별로 풀고, 모두 맞힌 레슨은 본문을 읽지 않아도 완료로 인정합니다 |
| `/modules/[module]/recall` | 백지 복습: 자료를 보지 않고 모듈의 핵심을 써 본 뒤 제출하면 비교 자료가 열립니다 |
| `/modules/[module]/assignment` | 과제: 요구사항, 작업 공간(코드 셀 실행·답안 작성·자동 저장), 자동 테스트, 자기 점검 기준, 심화 문제 |
| `/modules/[module]/review` | 복습 노트: 틀린 확인 문제, 보완 필요로 표시한 서술형·출력 예측·백지 복습 |
| `/progress` | 진도: 최근 학습에서 이어갈 내용, 분야별 진행, 개념별 완료 상태와 기수 일정 |
| `/feedback` | 내 복습: 모듈별로 다시 볼 문항 |
| `/chat` | 운영자 채팅(실시간, Enter로 보내기, Shift+Enter 줄바꿈) |
| `/login`, `/account`, `/privacy` | Google 로그인, 내 계정(탈퇴), 개인정보처리방침 |

예전 8주 구성의 주소(`/weeks/...`)는 그 단계를 이어받은 레슨이나 과제로 보냅니다(`src/content/curriculum/legacy.ts`).

## 학습 흐름

1. **레슨 완료**: 실습 탭에서 확인 문제를 모두 맞힌 뒤 "레슨 완료"를 누릅니다. 진단 평가에서 그 레슨의 확인 문제를 모두 맞혀도 완료로 인정됩니다. 서술형, 출력 예측, 코딩 실습은 권장 활동이며 완료 조건에 들어가지 않습니다(`src/lib/study.ts`).
2. **진행 방식**(운영 설정): 기본값인 **미완료 경고**에서는 어떤 레슨이든 열 수 있고, 먼저 마치면 좋은 선수 레슨이 남아 있으면 경고만 보여 줍니다. **잠금**에서는 모듈 안에서 앞 핵심 레슨을 끝내야 다음 핵심 레슨이 열리고, 핵심 레슨을 모두 끝내야 보충·심화 레슨과 백지 복습·과제가 열립니다. 관리자는 진행 방식과 관계없이 모든 레슨을 봅니다.
3. **코드 셀과 코딩 실습**: 본문의 코드 셀은 그대로 실행해 보는 완성 예제이고, 코딩 실습은 시작 코드의 `TODO`를 채우는 문제입니다. 실습의 **채점**은 빈 이름공간에서 작성한 코드를 실행한 뒤 채점 코드(`@test` 항목)를 이어서 실행해 항목별 통과 여부를 보여 줍니다. 힌트는 한 단계씩 열리고, 모범 답안은 모든 항목을 통과했거나 한 번 이상 채점하고 힌트를 모두 본 뒤에만 서버에서 받아 옵니다(`src/lib/labActions.ts`). 모든 코드는 브라우저의 Pyodide 워커에서 실행되며 서버로 보내지지 않고, 30초가 넘으면 멈춥니다.
4. **서술형과 백지 복습**: 서술형은 답을 저장하면 모범답안과 핵심 요소가 열리고, "핵심을 제대로 썼습니다" 또는 "보완이 필요합니다"로 스스로 평가합니다. 백지 복습은 문항마다 "충분히 떠올림" 또는 "보완 필요"로 표시합니다. 보완이 필요한 답은 복습 노트에 남습니다.
5. **과제**: 코드와 답안을 작업 공간에 작성합니다. 작업은 자동 저장되며, 자동 테스트와 점검 기준으로 직접 확인합니다.

## 로그인과 접근 범위

별도 회원가입 화면은 없습니다. Google 로그인 시 Google이 확인한 이메일과 사용자 식별자를 서버 DB에 저장하고, 처음 로그인한 사용자의 계정을 자동으로 만듭니다. 세션은 서명된(JWT, `SESSION_SECRET`) httpOnly 쿠키로 관리합니다(`src/lib/session.ts`, `src/lib/dal.ts`).

- 로그인하지 않은 방문자는 메인 화면, `/curriculum`, `/tracks/[track]`까지 볼 수 있습니다. 모듈·레슨·실습·과제·내 진도·내 복습·채팅과 레슨 이미지는 로그인이 필요하며, 로그인한 뒤 원래 페이지로 돌아옵니다(`src/proxy.ts`).
- 운영 환경에서 관리자는 **`ADMIN_EMAILS`에 지정한 이메일**로만 새로 지정됩니다. 첫 가입자 자동 관리자 지정은 로컬 개발에만 적용합니다.
- `/account`에서 확인 창을 거쳐 탈퇴할 수 있으며, 탈퇴하면 학습 기록, 과제 초안, 제출물, 채팅이 함께 삭제됩니다. 마지막 남은 관리자 계정은 탈퇴하거나 강등할 수 없습니다.

## 운영자 화면

`/operator/*`는 관리자 역할로만 접근할 수 있습니다(`src/proxy.ts`에서 1차 확인, 각 페이지의 `requireAdmin()`으로 재확인). 문항 정답과 해설은 각 활동의 공개 조건에 따라 학습자에게 표시됩니다.

| 경로 | 내용 |
| --- | --- |
| `/operator` | 대시보드: 새 메시지·스터디원 수, 이번 주 일정, 모듈별 학습 현황 |
| `/operator/members`, `/operator/members/[id]` | 스터디원 목록(권한 부여·회수, 계정 삭제)과 한 명의 학습 기록 전체(모듈별 레슨 진행, 확인 문제 오답, 서술형, 출력 예측, 코딩 실습, 백지 복습) |
| `/operator/members/answers` | 서술형 답안과 백지 복습을 문항별로 모아 비교 |
| `/operator/content`, `/operator/content/[module]` | 모듈별 레슨 수·문항 수·완료 수, 레슨별 정답·해설·모범답안과 정답률이 낮은 문항 |
| `/operator/chat`, `/operator/chat/[userId]` | 스터디원별 채팅(실시간). 확인 창을 거쳐 한 명과의 대화 전체 또는 모든 채팅을 지울 수 있습니다(되돌릴 수 없음) |
| `/operator/settings` | 진행 방식(미완료 경고·잠금), 기수 시작일 |
| `/operator/system` | DB·디스크·메모리 상태와 최근 서버 오류 |
| `/operator/security` | 보안 사건·이벤트·IP 규칙([보안 운영 개요](../operations/security.md)) |

운영자 통계는 스터디원의 기록만 셉니다. 진단 평가로 인정한 레슨도 완료로 집계합니다.
