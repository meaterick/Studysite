두 검토본을 `f335568`의 구현과 대조한 뒤 승인받은 범위를 반영했다. 원 검토본은 당시 관측 기록으로 유지하며, 현재 동작은 아래 구현과 생성 커리큘럼을 기준으로 확인한다.

## 반영한 내용

- 비핵심 레슨의 명시적 `requires`를 선수관계 안내에 반영했다. 명시하지 않은 레슨만 모듈 핵심 레슨 전체를 선수로 사용한다. 확장 레슨 전체와 캡스톤·일부 선택 레슨에 필요한 선수를 명시했다. 접근 잠금 규칙은 유지한다.
- 캡스톤 준비 안내를 `/curriculum/details#capstone-plan`에서 잠금·로그인 없이 볼 수 있게 했다. 레슨과 공개 안내가 같은 일정 데이터를 사용하며, 진도 화면도 공개 안내를 가리킨다. 준비 시점은 트랙 완료 주까지이며 공유·발표는 선택이다.
- 8개 과제 요약을 자기 점검 방식으로 수정하고, 생성 문서에서 운영자 채점을 뜻하는 제목과 배점 열을 제거했다. 내부 콘텐츠 검증용 배점·이전 설정 호환 데이터는 유지했다.
- RAG 과제의 검색 비교 코퍼스·골든셋·시작 코드·모범답안·테스트를 함께 갱신했다. 같은 8문항에서 MRR은 단어 0.8375, 글자 0.9375, 하이브리드 0.875다. 하이브리드가 항상 더 좋다는 가정은 제거했다. 다른 RAG·에이전트 예제의 외부 동아리 규칙은 가상 데이터임을 본문과 실습에서 명시했다.
- 트랙·분야 이름을 단일 출처로 정리하고 분야 소개의 주요 누락 주제를 보완했다. 과정 개요와 이용 방법의 링크 이름을 구분하고 개념과 레슨의 다대다 관계를 설명했다.
- 개념 ID를 유지하며 함수·가변성의 표시 번호를 7·8로 정리했다. 개념 선수 번호 검사, 표본·손실 관련 선수, 회귀 지표·소프트맥스 표제어를 보강했다. 가능도(우도)의 표기를 정리했다.
- 생성 데모의 NLL을 학습 데이터 손실로 명시하고 분할·평가 생략을 설명했다. 회귀 평가 링크와 비교표·모범답안도 함께 수정했다.
- 입문 코드·실습에 후속 문법 안내와 지금 수행할 범위를 표시했다. 용어 미니 사전, Python 진릿값·식별자·몫/나머지·반올림 설명, 다트머스·역전파 출처를 보완했다.
- RL 기초는 선택 레슨으로 유지하고 선호도 학습 본문에 필요한 최소 용어를 설명했다. 캡스톤 주제·논문 표에는 핵심·보충·확장 구분을 표시하고 선택 심화 레슨이 없는 모듈도 안내한다.

## 원 검토 제안에서 조정한 사항

- 실제 바이그램 코퍼스에서 `은` 다음은 공백 2회다. `이` 다음은 `터` 2회, `면` 1회, 공백 1회이므로, 원 검토본의 대체 문항 제안인 `2/3`은 사용하지 않는다. 기존 0.75 문항은 실습과 별개인 가상의 횟수표라고 명시했다.
- 학습 루프 그림에는 이미 갱신 수식이 있었다. 새 노드 대신 파라미터 갱신 라벨을 보완했다.
- f-string은 이진 부동소수점 표현 오차를 해결하지 않는다. 출력 자릿수 지정과 정확한 십진 계산을 구분한다.
- 모든 분야 소개에 모듈 제목을 강제하거나 모든 모듈에 선택 레슨을 추가하지 않았다. 16주 일정 재편·모듈 분할·주당 시간 상한 강제도 보류했다.
- 채점·점수 등의 단어를 전역 금지하지 않았다. 모델 평가·자동 테스트에는 필요한 용어다.

## 검증

- `npm run test:curriculum`: 선수관계·순환·확장 준비·개념 순서·잠금과 안내 경로·이름·과제 요약 회귀 검사.
- `npm run validate:content`, `npm run docs:check`, `npm run lint`, `npm run build`.
- `npm run check:labs -- course-overview`, `python-flow`, `llm-systems`: 본문 Python 셀·실습·예측·RAG 과제 참조 노트북 실행.
- `npm run test:security`, `npm run test:security:http`: 기존 검사와 잠금 모드의 캡스톤 준비 안내 접근 검사.

기존 `llm-systems`의 핵심 레슨 9개 권고 경고는 남는다. 일정과 모듈 분할을 보류한 범위에 해당한다.
