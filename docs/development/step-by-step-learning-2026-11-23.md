# 단계별 학습 보완 — 2026-11-23

[문서 홈](../README.md) · [편집 안내](../contributing/content-authoring.md) · [집계표](../curriculum/coverage.md)

입문자가 공식과 코드를 한 단계씩 따라갈 수 있도록 트랙 0·2~7과 선택 분야(T·X)의 레슨을 검토하고 보완했다. 트랙 1(Python)은 같은 기준으로 먼저 보완해 main에 반영했다(`39fb601`~`d33455a`). 완료 조건인 확인 문제 835개는 바꾸지 않았다. 새로 넣은 실습과 출력 예측은 완료 조건에 들어가지 않으며, 기존 문항의 `key`도 그대로 두었다.

## 검토에서 확인한 점

- 수학·머신러닝 레슨에서는 공식 다음에 결론이나 코드가 바로 이어지는 곳이 많았다. 작은 숫자로 중간값을 직접 따라가 볼 단계표가 부족했다.
- 실행 결과 블록은 10개 레슨에만 있었다(33개, 모두 Python 분야). 다른 분야에서는 코드를 실행하기 전에 기대 결과를 볼 수 없었고, 본문에 적은 수치가 실제 출력과 같은지 검사하는 장치도 없었다.
- 레슨 실습은 여러 단계를 한꺼번에 요구하는 문제로 시작했다. 한 줄이나 함수 하나만 채우는 준비 단계가 없었다.
- 3-1의 NumPy 레슨은 정수 배열의 기본 자료형을 `int64`로 설명했다. 학습자의 브라우저 실행 환경(Pyodide 0.29.5, wasm32)에서는 `int32`가 나온다.

## 반영한 내용

### 공통 형식

- **손계산 단계표**: 공식이나 알고리즘마다 작은 입력으로 중간값을 한 줄씩 적은 표를 두었다. 바로 아래 코드 셀이 같은 값을 다시 계산하고, 실행 결과 블록으로 결과를 보인다.
- **실행 결과 블록**: 33개(10개 레슨)에서 209개(112개 레슨)로 늘었다. 모두 코드 셀 바로 아래에 있어 `check:labs`가 실제 출력과 비교한다.
- **직접 해 보기**: 값을 바꿔 다시 실행해 보는 `:::task` 콜아웃 23개를 넣었다.
- **준비 실습**: 본 실습 앞에 빈칸 하나만 채우는 실습(`key: "ex0"`) 47개를 넣었다. 화면에서는 "실습 1"로 표시되고 기존 실습의 번호는 하나씩 뒤로 밀린다. 학습 기록은 `레슨id/키`로 저장되므로 기존 기록은 그대로 연결된다.
- **출력 예측**: 112개에서 194개로 늘었다. 레슨에서 다룬 연산의 결과를 실행 전에 적어 보게 한다.

### 주요 손계산 예제

- 4-2 선형 회귀: 1차원 최소제곱 계산표(`w = 2.5`, `b ≈ −0.667`).
- 4-2 로지스틱 회귀: 점수 → 확률 → 기울기 → 갱신 → 새 확률로 이어지는 한 번의 갱신을 6단계 표로 나눴다.
- 4-3 규제: 1차원 Ridge 계수 `w* = 31 / (14 + λ)`를 λ마다 계산하고 오차 제곱합과 규제항을 함께 적은 표.
- 4-3 교차 검증: `KFold`가 나눈 인덱스의 실행 결과.
- 5-1 퍼셉트론: AND 함수를 학습률 0.1로 학습하는 과정을 샘플마다 추적한 표.
- 5-2 초기화: 가중치 표준편차와 fan_in을 바꿔 가며 `z`의 분산이 `fan_in · Var(w)`와 같은지 재는 코드(샘플마다 새 가중치를 뽑는다).
- 5-3 합성곱: 커널을 겹친 창마다 원소별 곱의 합을 적은 표.
- 6-1 self-attention: 점수·스케일링·지수·가중치·가중합을 토큰마다 적은 표.
- 6-2 사전학습: 정답 확률 1/2, 1/4, 1/8에서 손실과 perplexity 4를 계산하는 예.

### 오류 수정

- 3-1 NumPy 자료형(`b371215`): 학습자 환경에서 `np.array([1, 2, 3]).dtype`은 `int32`이고 64비트 CPython에서는 `int64`다. 본문에 실행 환경에 따라 기본 정수 크기가 다르다는 설명을 넣고, 자료형을 출력하는 코드는 결과 블록 없이 셀을 따로 두었다. 확인 문제 c5는 정답을 그대로 두고 해설만 "정수 배열"로 고쳤다. 출력 예측 p1은 `int32` 출력을 정답으로, `int64` 출력을 다른 정답으로 인정한다. pandas의 기본 정수 열은 두 환경 모두 `int64`다.

### 검사와 편집 기준

- `check:labs`(`e0590e8`): 본문 코드 셀 바로 아래의 실행 결과 블록을 그 셀의 실제 출력과 비교한다(줄 끝 공백은 무시). 셀마다 표준 출력을 따로 받는다.
- `validate:content`: 수학·데이터 처리·머신러닝·딥러닝 분야 핵심 레슨의 예상 시간 경고 기준을 60분으로 정했다(기본 45분, Python 분야 75분).

## 학습 시간과 일정

핵심 레슨의 예상 시간 합계는 4080분(68.0시간)에서 4790분(79.8시간)으로 늘었다. 새 실습(8분), 출력 예측(2분), 코드 셀(1~3분)과 늘어난 본문 분량이 예상 시간 계산에 들어간다. 16주 기본 일정의 평균은 주당 약 5.0시간이다. 다만 9주(4-1·4-2)는 460분(7.7시간)으로 기본 일정의 기준인 주당 4~7시간을 넘고, 4주(2-1·2-2)는 415분(6.9시간)이다. 새 실습과 출력 예측은 완료 조건이 아니어서 학습자가 건너뛸 수 있다. 주 배정은 바꾸지 않았다.

## 검증

- `npm run validate:content`: 오류 0건. 경고 1건은 기존의 6-3 핵심 레슨 9개 권고다.
- `npm run docs:check`, `npm run lint`, `npm run typecheck`, `npm run test:curriculum`(10개 통과), `npm run build`.

- 학습자 실행 환경과 같은 Pyodide 0.29.5(Node.js)로 본문 코드 셀 514개, 실행 결과 블록 209개, 출력 예측 194개를 실행했다. 실습 207개는 모범 답안이 통과하고 시작 코드가 통과하지 않는지 확인했다. 문제는 0건이며, 3-1의 자료형 차이도 이 검사로 찾았다. 이 검사 스크립트는 저장소에 넣지 않았다.
