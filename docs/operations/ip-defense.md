# IP 차단과 반복 탐지

[문서 홈](../README.md)

운영자 메뉴의 **보안 센터 → 차단 IP**에서 관리한다. 기존 DB 관리자만 변경할 수 있다.
로그의 IP를 누르면 해당 주소를 필터하고 관리 양식에 채운다. IPv4/IPv6 단일 주소만 지원하며 CIDR 대역은 받지 않는다.

## 차단·해제

- 사유와 기간(15분·1시간·24시간·7일·30일)을 선택하고 `IP 차단` 또는 `허용 목록에 등록`을 누른다.
- 수동 규칙은 자동 탐지보다 우선한다. 같은 IP를 다시 등록하면 운영자가 선택한 규칙으로 교체한다.
- IP 규칙은 최대 500개이며 오래된 수동 규칙을 임의로 밀어내지 않는다. 한도에 도달하면 탐지 경고는 남고 새 차단은 생성되지 않는다.
- `해제`는 즉시 반영한다. 만료 시각이 지난 규칙은 물리 정리 전에도 적용하지 않는다.
  해제 시 해당 IP의 탐지 카운터도 비워 이전 신호로 즉시 재차단되는 것을 막는다.
- 규칙과 탐지 카운터는 SQLite에 저장해 재시작·겹치는 배포 프로세스 사이에 유지한다.
- 차단된 IP의 새 웹 요청은 정적 파일·API를 포함해 403/no-store/Retry-After로 응답한다.
  차단 이전에 열린 채팅 스트림도 데이터를 보내기 전에 다시 검사하고, 조용한 연결은 다음 heartbeat(최대 약 25초)에 닫는다.
- 방화벽 규칙을 수정하는 기능이 아니다. 앱까지 오는 HTTP 요청에 적용하며 이미 진행 중인 일반 응답을 강제 종료하지 않는다.

## 탐지 기준

5분 집계창은 각 IP·종류의 첫 신호부터 시작한다. 아래 기준을 넘으면 한 집계창에서 한 번 경고한다.

| 근거 | 기준 | 조치 |
| --- | --- | --- |
| 알려진 민감 경로 탐색 | 서로 다른 3경로 이상·10회 이상, 또는 경로 수와 관계없이 30회 이상 | 높은 위험 경고 + 기본 15분 자동 차단 |
| 로그인 실패·유효하지 않은 세션 | 인증 관련 신호 20회 | 경고만 생성 |
| 권한 없는 접근 | 신호 20회 | 경고만 생성 |
| nginx의 일반 404 | 서로 다른 10경로 이상·20회 이상 | 경고만 생성 |
| nginx의 요청·연결 제한 429 | 60회 | 경고만 생성 |

민감 경로는 .env·.git·WordPress 로그인·phpMyAdmin·PHPUnit·actuator 등 기존 탐색 패턴이다.
로그인 만료·취소나 일반 404만으로 자동 차단하지 않는다. 탐지는 침입 성공을 뜻하지 않는다.
허용 IP에서도 경고는 남기지만 자동 차단하지 않는다. 현재 DB 관리자 세션의 민감 경로 요청은 탐지 집계에서 제외한다.
자동 차단을 끄면 이후 새 자동 차단만 중지하며 이미 적용된 규칙은 해제하거나 만료를 기다린다.

## nginx 수집

- 앱 시작부터 10초마다 다음 최대 256KB를 읽는다. 커서를 DB에 저장하고 트랜잭션으로 중복 처리를 막는다.
- 첫 연결은 현재 파일 끝에서 시작해 배포 전의 요청으로 새 경고를 만들지 않는다.
  로그 회전·잘림은 감지하고 새 파일부터 읽는다. 미완성 마지막 줄은 다음 수집까지 기다린다.
- 5분보다 오래된 행과 미래 시각·잘못된 행을 제외한다. 현재 파일만 읽으므로 회전 전에 읽지 못한 기록은 놓칠 수 있다.
- 민감 경로 탐색은 앱에서 이미 집계하므로 nginx 404에서 다시 세지 않는다. nginx 경고로 자동 차단하지 않는다.
- 마지막 성공한 수집 시각과 해석 건수를 화면에 표시한다. nginx flush와 수집 간격만큼 반영이 늦을 수 있다.
- 메모리·디스크를 제한하기 위해 탐지 집계는 최대 5,000개, 비활성 10분 이후 정리(매시간)한다.
  일반 보안 기록은 기존 30일·10,000개 묶음 제한을 유지한다.

## 본인·운영자 보호와 복구

- 직접 입력한 현재 접속 IP의 수동 차단을 거부한다. 신뢰할 본인 IP가 없으면 수동 차단을 저장하지 않는다.
- 내부·루프백·링크 로컬·멀티캐스트 주소는 차단하지 않는다. IPv6 축약·대문자와 IPv4-mapped IPv6를 정규화해 별도 IP로 우회하지 못하게 한다.
- 유효한 서명뿐 아니라 **현재 DB에서 관리자 역할인지** 확인한 세션만 IP 차단을 우회해 해제할 수 있다.
  오래된 admin 역할 JWT라도 DB가 member이면 우회할 수 없다.
- 학교·기숙사 NAT처럼 공유 IP는 다른 이용자도 차단될 수 있다. 확인된 공유 IP는 허용 목록으로 관리한다.
- SSH 등 호스트 접근이 가능하면 런타임 환경에서 `SECURITY_IP_ENFORCEMENT=0`을 설정하고 앱을 재시작해 복구할 수 있다.
  이 모드에서는 IP 차단 적용과 새 자동 차단을 중지하며 로그인·관리자 인증은 유지한다. 복구 후 1로 되돌린다.
- `TRUST_PROXY=1`과 nginx의 X-Real-IP 덮어쓰기, 앱 loopback 바인딩을 전제로 한다.
  CDN 뒤에서는 CDN IP가 보일 수 있으므로 신뢰할 원 IP 복원을 구성하기 전 자동 차단을 중지해야 한다.
- 새 버전 배포 후 본인 IP를 현재 접속 정보로 확인하고 필요한 허용 IP를 등록할 수 있다.

## 범위와 검증

OCI 방화벽·포트 스캔·SSH 접속을 탐지하는 호스트 IDS가 아니다. 그 기록은 OCI Flow Logs와 호스트 인증 로그에서 확인한다.
요청 쿼리·본문·쿠키·OAuth 코드 대신 경로, IP, 횟수와 제한된 사유·근거만 보관한다.

`npm run test:security`와 `npm run test:security:http`는 IPv6 정규화, 본인·권한 보호, 모든 경로의 차단, 관리자 복구,
만료·해제·허용 목록, 자동 차단·경고 기준, 창 초기화, nginx 커서·회전·부분 행,
다른 프로세스에서의 지속성, 저장 상한을 검증한다. 추가로 lint·TypeScript·프로덕션 빌드와
standalone HTTP 검사에서 실제 관리자 양식 및 403 적용을 확인한다.


## 보안 센터의 화면

- **요약**: 활성 차단 수, 24시간 탐지 경고·차단 요청·한도 초과, 최근 탐지, 반복 신호 IP.
- **차단 IP**: 차단 중 / 허용 / 전체 보기, IP 일부·자동/수동 검색, 10개 단위 페이지. 사유, 남은 시간(조회 시점), 만료·설정 시각, 24시간 거절 횟수·마지막 거절, 즉시 해제와 IP별 기록 링크.
- **보안 기록**: 탐지 경고 / 규칙·정책 변경 / 전체, 기간·종류·위험도·IP 필터, 50개 단위 페이지. ‘탐지 근거·대응’을 펼쳐 근거, 계정, 첫 발생 시각 확인.
- **웹 요청**: nginx 실패 응답과 수집 상태를 따로 표시. 앱 집계와 합산하지 않는다.
- **서버 점검**: 운영 배포 때 수행한 읽기 전용 로컬 포트·SSH 전역 설정·패키지·러너 권한 스냅숏. 서버에 HTTP 요청할 때 명령을 실행하지 않는다. 외부 접근성이나 침해 여부를 판정하는 스캐너가 아니다.

DB v4는 규칙 변경 이력을 별도 테이블에 남긴다. 교체 전 설정도 보존하고 해제·만료를 기록하며 30일·3,000건으로 제한한다. 기존 규칙은 `existing`으로 한 번 옮기며 이전 변경 이력은 복원하지 않는다. 만료는 즉시 적용에서 제외되고 조회·저장·주기 정리 시 한 번 기록한다. 이력은 DB 백업에도 포함된다.

`scripts/deploy/security-inventory.py`는 키·환경변수·인증 로그 내용·프로세스 인수·리스닝 IP 주소를 수집하지 않는다. `ss`, `sshd -T`, `dpkg-query`, `sudo -n -l`의 허용된 필드만 `DATA_DIR/host-security.json`에 원자적으로 저장(0600)한다. 명령별 8초 제한, 실패 항목은 미확인으로 표시한다. 전체 파일은 관리자 화면에서만 읽고 배포 로그에는 DNS/앱 포트, 선택 SSH 설정, 패키지, 전체 sudo 여부만 출력한다. 현재 앱 계정도 이 파일을 수정할 수 있으므로 침해 후 증거 원본으로 신뢰해서는 안 된다. 실제 인증 이벤트 수집과 외부 별도 로그 저장은 이 변경에 포함되지 않는다.
