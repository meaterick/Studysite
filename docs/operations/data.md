# 데이터 저장소

[문서 홈](../README.md) · 경로와 명령은 저장소 루트 기준입니다.

## 저장 위치

서버의 데이터는 모두 `DATA_DIR`(기본 `data/`) 아래에 있습니다.

| 위치 | 내용 |
| --- | --- |
| `aegis.db` | 계정, 학습 기록, 과제 제출과 채점, 채팅, 운영 설정, 보안 기록(SQLite, `src/lib/db.ts`) |
| `drafts/<사용자 id>/<과제 키>.json` | 과제 작업 공간의 자동 저장 초안(`src/lib/assignmentDraftStore.ts`) |
| `uploads/<제출 id>/` | 제출본(`notebook-v<N>.json`)과 첨부 파일(최대 3개, 각 5MB, 합계 9MB) |

Node.js에 들어 있는 `node:sqlite`를 쓰므로 따로 설치할 것이 없습니다. 계정을 삭제하면 그 사용자의 학습 기록, 초안, 제출물, 대화가 즉시 함께 삭제됩니다.

## 학습 기록의 형식

학습 기록은 레슨 id를 기준으로 저장합니다(레슨 진행, 확인 문제, 서술형, 출력 예측, 코딩 실습, 백지 복습). 레슨 id, 문항 key, 과제 키, 과제 셀 id는 저장된 기록과 연결되므로 한 번 정하면 바꾸지 않습니다. 예전 8주 구성에서 쓰던 단계 기준의 기록은 DB에 남아 있지만 지금 사이트는 읽지 않으므로, 학습자는 새 과정을 처음부터 시작합니다. 예전 주소(`/weeks/...`)는 대응하는 레슨이나 과제로 연결됩니다(`src/content/curriculum/legacy.ts`).

## 동시 접근과 구조 변경

- **WAL 모드**라 읽기와 쓰기가 서로 막지 않고, 무중단 배포 중 두 버전이 함께 떠 있어도 같은 DB를 안전하게 씁니다. "확인 후 생성"하는 작업은 트랜잭션 하나로 처리합니다.
- **쓰기 비용이 사용자 수와 무관합니다.** 확인 문제 하나를 저장하면 바뀐 행만 쓰고, 스터디원 관리·제출함 화면은 필요한 숫자만 DB에서 모읍니다.
- **구조 변경(마이그레이션)** 은 서버가 시작할 때 `src/lib/db.ts`의 `MIGRATIONS` 순서대로 자동 적용합니다. 무중단 배포 중에는 이전 버전이 아직 돌고 있으므로 열과 표를 **추가만** 하고, 지우거나 이름을 바꾸는 변경은 그 열을 더 이상 쓰지 않는 버전을 먼저 배포한 다음에 합니다.

## 백업

사이트는 데이터베이스의 백업 사본을 만들지 않습니다. 개인정보처리방침(`/privacy`)도 같은 내용을 안내하며, 탈퇴한 사용자의 기록은 삭제 즉시 서버에서 사라집니다. `DATA_DIR`이 있는 디스크가 고장 나면 데이터를 되살릴 수 없으므로, 서버 디스크의 상태는 `/operator/system`에서 확인합니다.

## 오류 기록

요청 처리 중 난 서버 오류는 최근 300건까지 DB에 남아 `/operator/system`에서 볼 수 있습니다(경로만 기록하고 쿼리 문자열은 남기지 않습니다). 전체 앱 로그는 `DEPLOY_DIR/logs/`에 있습니다([배포 안내](deployment.md)).
