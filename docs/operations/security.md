## 보안 기록

운영자 메뉴 **보안 기록**(`/operator/security`)에서 최근 24시간 요약, IP별 반복 신호,
로그인 성공·실패, 권한 거부, 요청 제한, 민감 경로 탐색과 백업 다운로드 이력을 확인합니다.
기간(24시간/7일/30일)·종류·위험도·정확한 IP로 검색하고 50개 묶음씩 넘길 수 있습니다.
각 기록에는 발생 횟수와 확인할 사항이 표시됩니다. 공격 성공 여부를 판정하는 화면은 아닙니다.

앱 이벤트는 5분 단위로 합산하고 최대 30일·10,000개 묶음만 보관합니다. nginx의
4xx·5xx 요청은 별도 JSON 로그에 기록하며 현재 파일 마지막 512KB의 최근 100건을 표시합니다.
nginx 로그는 매시간 회전 조건을 검사해 일별 또는 10MB 초과 시 잘라 최대 7개 회전 파일을 보관합니다.
파일 회전 후 과거 파일은 화면에서 읽지 않습니다. 로그에는 쿼리·쿠키·OAuth 코드·요청 본문을 저장하지 않습니다.
`TRUST_PROXY=1`은 앱이 loopback으로만 열리고 nginx가 `X-Real-IP`를 덮어쓸 때만 사용합니다.
현재 배포는 이 설정과 `SECURITY_NGINX_LOG=/var/log/aegis-security/events.log`, 읽기 권한을 자동 구성합니다.
프록시 파일을 읽을 수 없으면 화면에 연결 오류가 표시됩니다. 앱과 nginx 기록은 중복될 수 있어 합산하지 않습니다.

OCI 네트워크에서 차단된 패킷·포트 스캔이나 SSH 접속은 이 웹앱에서 볼 수 없습니다.
OCI VCN Flow Logs 및 호스트 인증 로그를 따로 확인해야 합니다. 배포 이전 요청은 소급 수집되지 않습니다.
코드 점검 결과와 남은 조치는 [보안 점검 보고서](../archive/security/security-review-2026-10-19.md)에 정리했습니다.

검증: `npm run test:security`, `npm run lint`, `npm run build`, `npm audit --omit=dev`.

### IP 차단·반복 탐지

`/operator/security`의 IP 관리에서 사유·기간을 정해 차단하거나 허용 목록에 등록하고 해제할 수 있습니다.
민감 경로 탐색이 5분 집계창 안에 3곳 이상·10회 이상(또는 30회 이상)이면 기본 15분 자동 차단합니다.
반복 인증·권한 실패, 다양한 404와 nginx 429는 경고로 표시합니다. 새 자동 차단을 중지하는 설정도 있습니다.
본인 IP 차단 방지, DB 기준 관리자 복구, IPv6 정규화, 재시작 후 유지 및 만료를 지원합니다.
공유 IP는 여러 이용자에게 영향을 줄 수 있으므로 필요한 주소는 허용 목록으로 관리해 주십시오.
상세 정책·수집 범위·복구 방법은 [IP 방어 운영 안내](ip-defense.md)를 참고하세요.

서버 노출과 침해 영향 검토: [2026-10-19 Nmap 위험 검토](../archive/security/nmap-risk-review-2026-10-19.md).

보안 센터의 탐지·대응 흐름, 로그인/CSP 추가 방어, SSH·방화벽 읽기 전용 수집기의 범위는 [보안 모니터링 운영 안내](security-monitoring.md)에 정리했습니다.

운영자 작업 흐름에 따른 화면 구성, 수집·저장의 효율 측정과 남은 위험은 [보안 구조·효율 점검](../archive/security/security-architecture-review-2026-10-19.md)에서 확인할 수 있습니다. `npm run bench:security`는 운영 데이터 없이 임시 DB로 비용을 측정합니다.
