# 보안 센터 운영·추가 점검

화면 재구성과 수집·조회 효율 점검은 [구조·효율 점검](security-architecture-review-2026-10-19.md)에 정리한다. 목록에서 한 탐지를 선택해 대응하며 완료 후에도 선택 URL을 유지한다. 보호 점검에 수집 상태·정책·보관 한도를 함께 표시한다.

## 이번 점검에서 보강한 경계

- 민감 경로는 최대 3회 디코딩해 환경·Git·SSH 키·DB 파일, 디렉터리 이동 및 알려진 관리 도구 탐색을 거절한다. 원본 쿼리와 요청 본문은 검사·저장하지 않는다. 학습 코드의 SQL·셸 문자열 때문에 차단하지 않는다.
- 서비스가 사용하는 GET/HEAD/OPTIONS/POST 외 메서드는 405로 거절하고 기록한다. 신규 API가 PUT/PATCH/DELETE를 사용하면 허용 정책과 검증을 함께 수정해야 한다.
- Google 로그인 시작은 IP당 5분 30회, callback은 60회다. 한도 초과는 429·Retry-After·no-store로 응답한다. SQLite에서 두 배포 프로세스에 공유하고 만료 후 정리한다. 신뢰할 IP가 없으면 IP 제한을 적용할 수 없으므로 프록시 설정 확인이 필요하다.
- 서명 검증된 OAuth nonce를 외부 token exchange 전에 한 번만 사용 처리한다. 원문 상태·인증 코드를 저장하지 않고 nonce 해시만 10분·최대 5,000개 보관한다. 재시도는 새 로그인으로 시작한다.
- 동적 HTML의 스크립트는 요청마다 새 CSP nonce를 사용한다. Next 런타임과 테마 스크립트에 같은 nonce를 붙이고 외부 입력의 nonce/CSP 헤더를 덮어쓴다. production script-src의 unsafe-inline을 제거했다. 스타일은 KaTeX/Monaco 때문에 inline을 허용하며 Pyodide는 기존 전용 worker CSP를 유지한다. 모든 HTML은 기존에도 쿠키 기반 동적 렌더링이었다. 정적 파일·worker의 IP 게이트는 유지한다.
- 세션·OAuth 상태 토큰의 길이를 제한한다. 기존 DB 권한 재검사, 업로드 한도·파일 경로 제한, 첨부 다운로드 강제, 서버 액션 출처 검증, SQL 매개변수 바인딩도 재확인했다.

## 탐지·대응 흐름

민감 경로, 인증·권한 실패, nginx 404/429에 출처 검증 실패·비허용 메서드·로그인 한도 초과·SSH 인증 신호를 연결한다. 확률 점수를 만들지 않으며 탐지는 침해 성공 증명이 아니다.

| 신호 | 집계창/기준 | 대응 |
| --- | --- | --- |
| 민감 경로 | 첫 신호부터 5분, 3경로·10회 또는 30회 | 웹 경고 + 정책 사용 시 15분 웹 IP 차단 |
| 인증·권한 실패 / 로그인 제한 | 첫 신호부터 5분, 20회 | 대응 목록·경고, 자동 IP 차단 없음 |
| 출처 검증 실패 / 비허용 메서드 | 첫 신호부터 5분, 10회 | 대응 목록·경고, 자동 IP 차단 없음 |
| nginx 일반 404 | 5분, 10경로·20회 | 경고만 |
| nginx 429 | 5분, 60회 | 경고만 |
| SSH 인증 실패 | 서버 발생 시각 기준 고정 5분창, 10회 | SSH 경고, 웹·SSH 자동 차단 없음 |
| root SSH 로그인 | 관측 건마다 기록, 같은 IP·5분창으로 대응 묶음 | 본인 관리 접속인지 검토 |

대응 목록은 이번 기능 이후의 탐지부터 생성된다. 이전 경고는 접근 기록에서 확인한다. IP·유형별로 미확인/확인 중/처리 완료/정상·오탐을 관리하며 완료·오탐은 사유가 필요하다. 모든 변경은 DB 관리자 권한을 재확인하고 이력을 남긴다. 같은 집계창의 추가 신호는 완료를 다시 열지 않고 새 집계창에서 재발하면 미확인으로 되돌린다. 최근 신호 수는 해당 집계창의 수이며 총 누적 공격 수가 아니다. 빈도를 줄이기 위해 임계치와 이후 10회 단위에서 갱신된다.

보관: 사건 최대 30일·1,000개 유형/IP 묶음, 대응 이력 3,000건(부모 사건 삭제 시 함께 삭제). 앱 보안 이벤트는 기존 30일·10,000개 묶음, 규칙/탐지 집계 한도도 유지한다. 백업에는 DB에 포함된 이력이 들어간다.

## SSH·방화벽 수집기

배포가 `scripts/deploy/security-collector-install.sh`로 root 소유 `/usr/local/lib/aegis-security/collector.py`와 systemd timer를 설치한다. 코드·부모 디렉터리는 앱/러너가 수정할 수 없는 root 소유다. 앱에 journal이나 방화벽 sudo 명령을 추가하지 않는다. 기존 배포 계정의 무암호 전체 sudo 위험을 해소하는 변경은 아니며 계정 분리는 여전히 필요하다.

1분마다 고정된 journalctl/iptables/ip6tables 조회만 수행한다. 네트워크 스캔·방화벽 변경·로그인 차단은 하지 않는다. 원본 journal은 파일에 복사하지 않고 sshd 메타데이터와 Failed/Accepted password/publickey 형식만 해석한다. 사용자 이름·키·원문 메시지·프로세스 인수는 출력에 없다. SSH 방식과 root 여부, 발생 시각, IP, journal cursor의 해시만 보관한다.

고정 파일 `/var/lib/aegis-security/telemetry.json`은 root 소유·0640, 디렉터리는 root 소유·0750이고 앱 그룹에 읽기만 허용한다. 15분 범위에서 journal 최신 1,000행 중 해석한 인증 기록 200건을 표시하며 한도 도달을 표시한다. 모든 SSH 실패 형식이나 로그 레벨·다른 SSH 데몬을 지원하는 것은 아니다. 수집 실패·3분 이상 지연은 ‘공격 없음’과 구분해 표시한다.

앱은 15초마다 파일을 읽고 세대·이벤트 해시를 SQLite로 공유해 겹치는 프로세스에서 중복 집계를 막는다. 중복 방지는 30분·5,000개 제한이다. 오래되거나 미래·잘못된 스냅숏은 수집에 사용하지 않는다. 일부 기록이 한도·로그 회전·journal 설정으로 누락될 수 있다.

방화벽은 IPv4/IPv6 INPUT 규칙의 제한된 읽기 전용 해석이다. 전체 출발지 TCP 허용 포트와 단일 IP DROP/REJECT를 표시하고 앞선 전체 종료 규칙 또는 허용 포트 때문에 차단이 무력화되는 순서를 알린다. 조건부 규칙은 상세 확인 대상으로 표시한다. OCI·NAT·FORWARD·컨테이너·사용자 정의 체인·모든 확장 모듈의 실행 의미를 해석하지 않으므로 실제 외부 차단 검증을 대신하지 않는다. 앱 IP 목록과 호스트 방화벽 목록은 서로 다른 정책이다.

설치/조회 권한이 없으면 수집기 설치 단계는 경고로 남고 기존 웹 기능은 유지된다. 수집기 확인은 `systemctl status aegis-security-collector.timer`, `systemctl status aegis-security-collector.service`로 한다. 앱 계정을 분리하면 출력 디렉터리·파일의 읽기 그룹도 전용 그룹으로 다시 설정한다. 서비스가 root를 사용하므로 설치 코드는 검토된 main에서만 배포해야 한다.

## 남은 위험과 범위

- 앱과 self-hosted 러너의 실행 계정 공유 및 전체 sudo 권한은 계정·배포 구조를 별도로 이전해야 한다. UI의 점검 경고는 해결 완료 표시가 아니다.
- SSH/OCI 방화벽을 자동 변경하지 않는다. 관리자 접속 경로 확인 없이 22번·sudo 권한을 회수하면 접속·배포가 실패할 수 있다.
- DNS 요청, OCI 차단 패킷, 모든 포트 스캔·볼륨 DDoS, 실제 침해 성공 판정은 제공하지 않는다. 별도 Flow Logs·서비스 로그·외부 방어가 필요하다.
- root 공격자는 같은 서버의 코드·스냅숏·DB 로그를 변조할 수 있다. 독립된 외부 로그·백업 저장과 접근 통제를 권장한다.

근거: OWASP Logging/Denial of Service Cheat Sheets, Next 설치 버전의 Proxy/Server Actions/CSP 가이드, systemd journal 형식과 Ubuntu iptables 매뉴얼. 앱 동작과 한도는 저장소 코드·격리된 회귀/HTTP 테스트로 검증한다.
