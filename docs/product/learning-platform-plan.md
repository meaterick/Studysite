# Studysite를 Python과 AI 학습 플랫폼으로 확장한다

**기획 기준: 2026년 11월 2일 · 대상: meaterick/Studysite · 검토 커밋: 4decf9156f8c0653e651e875e7651519dbc0e44c**

**수정 기준: AI는 개념과 원리를 전달하는 지식 중심 과정으로 구성한다. AI의 캡스톤·프로젝트·제작 과제·제출·채점은 제외한다. Python의 실습·프로젝트 구성은 유지한다.**

상위 구조는 **Python·AI 두 분야 → 과정 → 모듈 → 레슨**으로 통일한다. Python은 직접 코드를 작성하고 문제를 해결하는 실용 과정으로, AI는 전체 그림에서 핵심 개념·작동 원리·해설 예시로 내려가는 지식 과정으로 구분한다. 같은 플랫폼에서 분야의 목적에 맞는 학습 경험을 제공한다.

AI는 기존 8주 자료의 이론·설명·사례를 12개 주제 모듈로 재구성한다. 기존 직접 구현·실험·평가 자료는 필요한 부분을 완성된 해설 예시로 전환한다. 학습자가 별도 결과물을 제작하거나 제출하는 흐름은 두지 않는다. 읽기 완료는 사용자가 직접 표시하고, 짧은 자기점검은 선택으로 제공한다.

이 문서는 **제품·교육·구조를 새로 설계한 제안서**다. 저장소에 관한 현행 사실은 고정 커밋 기준이며, 실제 사이트를 수정하거나 운영 데이터를 변경한 결과가 아니다. 신규 과정명·모듈·화면·URL·완료 정책은 제안이다. Python 학습시간은 기존 설계 추정을 유지하고, 프로젝트를 포함했던 AI의 기존 시간 추정은 폐기한다. AI 읽기 분량과 시간은 지식 레슨 편집 후 산정한다.

## 1. 분야별 학습 목적을 분명하게 나눈다

### 1.1 사이트의 역할과 학습 목표

사이트의 공통 약속은 **“전체 지도를 이해하고, 지금 배우는 내용의 의미와 다음 학습 위치를 알 수 있다”**이다. Python은 실행·수정·독립 구현을, AI는 개념·원리·사례 이해를 중심에 둔다.

| 분야 | 학습 목표 | 주요 콘텐츠 | 학습 완료 방식 |
|---|---|---|---|
| Python | 코드를 작성하고 파일·데이터 작업을 프로그램으로 해결한다 | 실행 예제, TODO 실습, 테스트, 실용 프로젝트 | 핵심 확인·대표 실습·과정 프로젝트 기준 |
| AI | AI 기술의 구조·작동 원리·차이·한계를 이해한다 | 설명 글, 개념 지도, 도식, 해설 수식·코드, 비교 사례 | 레슨 읽음·학습 완료 직접 표시; 자기점검 선택 |

기존 저장소의 AI 자료는 수학·Python·ML·DL·Transformer·LLM·RAG·에이전트와 과제·캡스톤을 포함한다. 문서 집계는 4부·8주·104단계다. 이는 기존 상태에 대한 설명이며 이번 AI 지식 과정에 모든 활동을 유지한다는 뜻이 아니다. 과제와 캡스톤은 새 AI 학습 구성에서 제외한다. ([기존 소개](https://github.com/meaterick/Studysite/blob/4decf9156f8c0653e651e875e7651519dbc0e44c/README.md), [기존 커리큘럼 현황](https://github.com/meaterick/Studysite/blob/4decf9156f8c0653e651e875e7651519dbc0e44c/docs/curriculum/coverage.md))

### 1.2 먼저 지원할 학습자

한국어로 자기주도 학습하는 프로그래밍 입문자와 AI 입문·중급 학습자를 기본 대상으로 가정한다. 기존 문서에서 확인된 이용자 조사 결과가 아니라 이번 기획의 대상 설정이다.

| 학습자 | 필요한 답 | 시작점 |
|---|---|---|
| 코딩이 처음인 사람 | 어떻게 첫 프로그램을 만드는가 | Python 기초 |
| 코딩 없이 AI를 이해하려는 사람 | AI는 무엇이고 어떤 구조로 작동하는가 | AI 전체 지도와 개념 입문 |
| AI 원리를 깊이 이해하려는 사람 | 데이터·수학·학습 계산이 어떻게 연결되는가 | AI 원리 이해 경로, 선택 수학 해설 |
| LLM 활용 기술이 궁금한 사람 | LLM·RAG·에이전트는 무엇이 다른가 | LLM·RAG·에이전트 이해 경로 |
| 기존 AI 학습자 | 기존 이론 내용과 기록을 어디서 이어 읽는가 | 기존 위치 연결·새 모듈 지도 |

AI 지식 과정은 Python 수료·코드 실행·API 계정·진단 통과 없이 시작할 수 있다. 낯선 용어와 수학은 해당 레슨 안에서 먼저 설명하고, 더 깊은 설명이 필요하면 관련 레슨으로 연결한다.

### 1.3 분야별 탑다운 학습 방식

| 구분 | 학습 흐름 | 레슨에서 보여줄 내용 |
|---|---|---|
| Python | 완성 결과 → 최소 실행 → 일부 수정 → 개념 이해 → 독립 적용 | 입력·출력 예시, 작은 코드, 실습·테스트 |
| AI | 전체 그림 → 시스템 흐름 → 구성 개념 → 작동 원리 → 해설 예시 → 요약 | 활용 사례, 구조도, 개념 비교, 계산·코드 해설 |

AI에서는 예를 들어 “RAG가 필요한 이유”를 먼저 설명한 뒤 검색→근거 제공→답변이라는 흐름을 보여주고, 청킹·임베딩·인용 같은 개념을 순서대로 설명한다. 독자가 직접 QA 시스템을 만들거나 평가셋을 제출할 필요는 없다.

### 1.4 영구 계층과 학습 경로

| 단위 | 역할 | 예시 |
|---|---|---|
| 분야 | 무엇을 배우는가 | Python, AI |
| 과정 | 어떤 범위를 학습하는가 | Python 기초, AI 원리와 활용 이해 |
| 모듈 | 이번에 다룰 주제는 무엇인가 | 함수, Transformer, RAG |
| 레슨 | 오늘 이해하거나 수행할 내용은 무엇인가 | 반환값, Attention의 Q·K·V |
| 학습 경로 | 목적에 맞는 레슨을 어떤 순서로 보는가 | 업무 자동화, AI 원리 이해, LLM 활용 기술 이해 |
| 일정 보기 | 학습 내용을 언제 읽는가 | 기존 8주 자료를 참고한 읽기 일정 |

학습 경로는 기존 레슨의 참조 목록이며 별도의 필수 계층이 아니다. AI의 경로 완료는 참조 레슨의 학습 완료 표시를 뜻한다. 프로젝트 수료나 실무 숙련을 인증하는 의미로 사용하지 않는다.

    Studysite
    ├─ Python
    │  ├─ Python 기초 (PY-F, 8모듈)
    │  ├─ Python 실전 활용 (PY-P, 4모듈)
    │  └─ AI를 위한 데이터 Python (PY-D, 4모듈)
    ├─ AI
    │  └─ AI 원리와 활용 이해 (AI-01~12)
    │     ├─ 전체 지도·추천 시작점
    │     ├─ AI 원리 이해 경로
    │     ├─ LLM·RAG·에이전트 이해 경로
    │     └─ 전체 읽기·선택 심화
    └─ 공통 기능
       ├─ 내 학습·검색·개념 색인·다시 보기
       └─ Python 실습·프로젝트 제출·피드백

초기에는 Python과 AI만 노출한다. 향후 다른 분야를 추가할 때 공통 분류와 검색·기록 기능을 재사용하고, 실습형인지 지식형인지를 과정별로 정한다. 홈의 플랫폼 소개와 분야 설명도 이 구분을 따른다.

## 2. Python은 독립 완주 과정으로 만들고 필요한 AI 역량을 연결한다

### 2.1 세 과정의 역할과 선수 관계

Python 영역은 **기초 → 실전 활용**과 **기초 → 데이터 Python**의 독립 완주 경로를 제공한다. Python을 직접 배우고 싶은 사람은 실습과 프로젝트로 학습한다. AI는 지식 전달형이므로 Python 수강을 요구하지 않는다. AI의 수식·배열·해설 코드를 더 깊게 읽고 싶은 사람에게만 관련 Python 레슨을 선택 참고로 연결한다.

기존 W1에는 최소 Python 문법, NumPy, 개발 환경이 함께 있고, W3에는 자동미분 코드를 읽기 위한 클래스·연산자 메서드·클로저·재귀가 다시 등장한다. 일반 Python은 독립 정본으로 확장하고 AI에서는 그 개념의 사용 맥락과 준비도 링크를 제공하는 구성이 적합하다. ([기존 W1](https://github.com/meaterick/Studysite/blob/4decf9156f8c0653e651e875e7651519dbc0e44c/docs/curriculum/week-01.md), [기존 W3](https://github.com/meaterick/Studysite/blob/4decf9156f8c0653e651e875e7651519dbc0e44c/docs/curriculum/week-03.md))

공식 Python 튜토리얼도 프로그래밍 자체의 완전 초보자보다 Python을 처음 배우는 프로그래머를 대상으로 한다고 안내한다. 따라서 공식 문서의 문법 목차를 그대로 옮기는 대신 첫 실행, 오류 읽기, 문제 분해, 결과 예측을 입문 과정에 별도로 설계한다. 아래 Python 세 과정은 기존에 완성된 독립 과정의 목록이 아니라 신규 제안이다. ([Python 공식 튜토리얼](https://docs.python.org/3/tutorial/))

| 과정 | 선수조건 | 최종 산출물 | 필수 학습시간 추정 | 우선 공개 범위 |
|---|---|---|---|---|
| PY-F Python 기초 | 프로그래밍 경험 없음 | 메모리의 작업 기록을 집계하는 작은 프로그램과 설명 | 24~32시간 | 첫 정식 공개의 완주 과정 |
| PY-P Python 실전 활용 | PY-F 핵심 역량 또는 진단 통과 | CSV 파일들을 읽고 요약 JSON/CSV를 만드는 도구 | 12~18시간 | 후속 독립 과정; AI 지식 학습의 필수 조건 아님 |
| PY-D AI를 위한 데이터 Python | 자료구조·반복·함수 역량 | 고정 데이터의 검사·집계·시각화 노트북 | 8~12시간 | D1/D2 우선, D3/D4 순차 확장 |

시간에는 읽기·연습·프로젝트가 포함되며 개인별 차이가 있다. 레슨은 대체로 기본 학습 15~30분과 실습 10~20분을 초기 편집 기준으로 삼되, 개념과 활동 수에 맞춰 나눈다. 실제 공개 시간은 초보 학습자 파일럿으로 보정한다.

### 2.2 PY-F: 작은 프로그램을 스스로 만드는 Python 기초

전체 결과물은 ‘작업 기록 집계기’다. 작업명과 시간으로 된 기록을 입력받아 전체 시간, 종류별 합계, 기준 이상인 기록을 출력한다. 첫 모듈에서 완성본을 실행하고 이후 각 모듈에서 그 구성 요소를 직접 만든다. 파일 저장과 외부 API는 다음 과정에서 확장하므로 기초 과정의 완주를 막지 않는다.

| 모듈 | 세부 레슨 구성 | 모듈 산출물 | 통과 기준 |
|---|---|---|---|
| F1 프로그램의 전체 모습과 첫 실행 | 입력→처리→출력; 코드셀과 스크립트; print와 실행 순서; 오류 마지막 줄과 줄 번호 | 예제 실행·수정 기록 | 값을 바꾸고 출력을 예측한다. 새 실행 상태에서 재실행하고 NameError와 SyntaxError를 구별해 한 번 수정한다 |
| F2 값과 표현식 | 변수·대입; 숫자/문자열/bool; 형 변환·f-string; 입력값 검증의 첫걸음 | 작업 시간·단가 계산기 | 문자열과 숫자의 차이를 설명하고 0·빈 문자열의 처리 결과를 확인한다 |
| F3 여러 데이터 다루기 | list와 인덱스·슬라이스; dict의 키·값; tuple/set의 필요; 복사와 변경 | list[dict]로 만든 작업 기록 5개 | 작업 종류를 중복 제거하고, 없는 키·빈 목록에서 생기는 결과를 예측한다 |
| F4 선택과 반복 | if/elif/else; for/range; 누적·조건 필터; while·종료 조건과 컴프리헨션 읽기 | 기준 시간 이상인 기록의 합계·건수 | 빈 목록·경계값·여러 항목에서 결과가 맞고 반복 종료 이유를 설명한다 |
| F5 함수로 문제 나누기 | 매개변수·반환값; 지역 범위; 기능별 분해; 기본 인수와 짧은 문서화 | 집계 기능을 나눈 2~3개 함수 | print하는 함수와 값을 반환하는 함수를 구별하며 각 함수를 새 입력으로 호출한다 |
| F6 맞는 코드인지 확인하기 | 기대 결과 먼저 쓰기; assert; traceback으로 원인 좁히기; 경계값·실패 사례 | 정상·빈 입력·잘못된 입력 테스트 | 의도적으로 넣은 결함을 테스트로 찾고 수정한다. 실패 원인을 한 문장으로 설명한다 |
| F7 코드를 읽고 나누기 | import와 모듈; 표준 라이브러리; 간단한 타입 힌트; 실행 진입점과 파일 분리 | 제공된 환경에서 실행하는 두 파일 | import 오류와 함수 내부 오류를 구별한다. 다른 사람이 함수 역할을 알 수 있다 |
| F8 기초 통합 프로젝트 | 요구사항을 예제로 바꾸기; 집계기 설계; 독립 구현·검증; 사용법과 한계 설명 | 작업 기록 집계기와 짧은 README | 시작 코드 없이 최소 기능을 구현하고 3개 이상 경계 테스트를 작성한다. 새 상태에서 재실행하고 한계를 설명한다 |

F1~F7은 F8의 작은 기능을 계속 축적한다. 모듈 실습에서는 시작 코드와 힌트를 제공하지만, F8에서는 새 요구사항을 추가해 독립 적용을 확인한다. 함수형 분해와 테스트를 먼저 익히고 클래스는 이 과정의 필수 조건으로 두지 않는다.

### 2.3 PY-P: 파일과 외부 데이터를 처리하는 실전 활용

최종 결과물은 여러 작업 기록 CSV를 읽어 정리하고 요약 파일을 저장하는 도구다. 먼저 제공된 작은 샘플 폴더로 학습하고 사용자가 선택한 데이터로 확장한다. 외부 API의 실시간 응답에 의존하지 않도록 고정 JSON 응답 파일로도 모든 기본 실습을 재현한다.

| 모듈 | 세부 레슨 구성 | 모듈 산출물 | 통과 기준 |
|---|---|---|---|

### 2.4 PY-D: AI 코드를 읽기 위한 배열·표·노트북

이 과정의 경계는 **데이터를 읽고 변환하는 Python 역량**이다. 미분, ML 알고리즘의 유도, 통계적 가설 검정까지 한꺼번에 넣지 않는다. NumPy 배열의 차원·shape·인덱싱·복사와 pandas의 표 선택·집계·시각화라는 공식 입문 범위를 교육 성과에 맞춰 편성한다. ([NumPy 공식 입문](https://numpy.org/doc/stable/user/absolute_beginners.html), [pandas 공식 입문](https://pandas.pydata.org/docs/getting_started/intro_tutorials/index.html))

| 모듈 | 세부 레슨 구성 | 모듈 산출물 | 통과 기준 |

| D4 AI 실습으로 넘기기 | X/y·샘플·특징; 데이터 분할 경계; 재현성 기록; 완성 AI 노트북 읽기 | 데이터→처리→모델→평가 흐름도 | 새 상태에서 전체 실행하고 각 블록의 역할을 설명한다. 학습용 통계를 어느 데이터에서 구해야 하는지 구별한다 |

D4의 데이터 누수는 규칙과 경계를 소개하는 수준으로 제한한다. AI-02에서는 split·전처리·평가 설계를 제공된 도식과 pipeline 예제로 설명한다. AI 학습자에게 pipeline 구현이나 검증 결과 제출을 요구하지 않는다. ([scikit-learn 공식 시작하기](https://scikit-learn.org/stable/getting_started.html))

## 3. AI는 12개 모듈의 지식 중심 과정으로 구성한다

### 3.1 과정 목표와 콘텐츠 범위

과정명은 **AI 원리와 활용 이해**로 제안한다. 학습 목표는 AI의 전체 구조, 학습과 추론의 차이, 주요 모델의 원리, LLM 활용 기술의 구성, 평가 방법과 한계를 이해하는 것이다. 배운 내용을 설명하거나 비교할 수 있도록 돕되 결과물 제작·보고서 작성·발표·제출·채점을 요구하지 않는다.

각 모듈은 다음 네 종류의 콘텐츠로 구성한다.

- **핵심 설명:** 개념·필요성·작동 흐름·한계.
- **도식과 비교:** 입력과 출력, 구성 요소, 비슷한 기술의 차이.
- **해설 예시:** 계산 과정, 주석이 있는 짧은 코드, 이미 만들어진 실험 결과나 사례.
- **선택 자기점검:** 개념 질문과 펼쳐 보는 해설. 점수·접근 제한·완료 조건과 연결하지 않음.

기존 직접 구현·실험 자료에는 gradient check, ablation, causal mask 검사, 근거·거절 평가, prompt injection 사례 등이 포함된다. 이러한 내용을 완성된 예제와 해설로 활용한다. 학습자가 같은 구현이나 검사를 수행해야 하는 과제는 두지 않는다. ([기존 W3](https://github.com/meaterick/Studysite/blob/4decf9156f8c0653e651e875e7651519dbc0e44c/docs/curriculum/week-03.md), [W4](https://github.com/meaterick/Studysite/blob/4decf9156f8c0653e651e875e7651519dbc0e44c/docs/curriculum/week-04.md), [W5](https://github.com/meaterick/Studysite/blob/4decf9156f8c0653e651e875e7651519dbc0e44c/docs/curriculum/week-05.md), [W7](https://github.com/meaterick/Studysite/blob/4decf9156f8c0653e651e875e7651519dbc0e44c/docs/curriculum/week-07.md))

| 수식·코드 심화 | 관심 모듈의 선택 해설 → 관련 Python 참고 | 원하는 주제의 계산·코드 표현 |

경로는 추천 순서이며 접근 제한이 아니다. 경로 완료는 참조 레슨을 사용자가 학습 완료로 표시한 상태다. 실무 역량·구현 능력·프로젝트 수행을 인증하지 않는다. API·JSON·NumPy 레슨 제작 여부와 관계없이 AI 지식 경로를 공개할 수 있다.

기존 AI의 64~90시간 추정은 구현·프로젝트를 포함한 설계여서 재사용하지 않는다. 새 읽기 시간은 설명·도식·예시 분량을 편집한 뒤 파일럿으로 보정한다.

## 4. 화면은 분야별 학습 방식에 맞게 구성한다

### 4.1 사이트맵과 화면별 역할

URL은 신규 제안이다. 분야와 과정의 분류는 공유하고, 화면의 주요 행동은 지식형·실습형에 따라 다르게 표시한다.

| 화면·권장 URL | 먼저 보여줄 내용 | AI 주요 행동 | Python 주요 행동 |
|---|---|---|---|
| 홈 / | Python·AI 소개, 최근 학습 위치 | AI 전체 지도·이어서 읽기 | 과정 선택·이어서 실습 |
| 분야 /learn/python, /learn/ai | 학습 목표·과정·추천 경로 | 관심 주제·추천 시작점 | 시작점·선수 역량 확인 |
| 과정 /courses/[course] | 전체 범위·모듈 지도·학습 방식 | 읽을 주제 선택 | 결과물·실습·평가 기준 확인 |
| 모듈 /courses/[course]/modules/[module] | 주제·위치·레슨 순서 | 읽기 시작·다시 보기 | 학습·실습 계속하기 |
| 레슨 /courses/[course]/lessons/[lesson] | 해당 분야의 공통 레슨 틀 | 읽음 표시·개념 이동·다음 읽기 | 실행·수정·실습 |
| 내 학습 /dashboard | 선택 과정·최근 위치·진행 상태 | 읽기 진도·다시 볼 내용 | 학습·실습·프로젝트·피드백 |
| 검색 /search | 분야·과정·유형 필터·개념 색인 | 개념·설명·관련 사례 찾기 | 레슨·실습·프로젝트 찾기 |
| 다시 보기 /review | 표시한 내용·개념 연결 | 다시 읽기·선택 자기점검 | 오답·미통과 실습 재시도 |
| 연습 /courses/[course]/practice | Python 실습 모음 | AI 과정에는 제공하지 않음 | 문제 풀이·실행 |
| 프로젝트 /courses/[course]/projects/[project] | Python 요구사항·자료·루브릭 | AI 과정에는 제공하지 않음 | 제작·제출·피드백 |
| 운영 /operator 하위 | 콘텐츠 검수·학습 지원 | 설명·사례·출처 관리 | 제출·피드백 검토 |

전역 메뉴는 ‘학습 분야 · 학습 지도 · 내 학습 · 검색’을 기본으로 한다. AI 레슨은 읽기 영역을 중심으로 두고 도식·수식·코드 해설을 접거나 펼칠 수 있게 한다. Python 레슨은 코드 편집·실행·결과 확인을 중심으로 한다. 모바일에서는 본문·목차·예시가 읽기 쉬운 순서로 배치되도록 한다.

### 4.2 과정 지도와 내 학습

AI 과정 지도는 “무엇을 이해하는가”와 개념 간 관계를 먼저 보여준다. 모듈 카드에는 제목·핵심 질문·설명 범위·읽기 상태·선택 심화를 둔다. 최종 결과물, 과제 마감, 제출·채점 대기는 표시하지 않는다.

Python 과정 지도는 최종 프로젝트·필수 모듈·실습·평가를 유지한다. 내 학습에서도 AI의 읽기 진행과 Python의 실습·프로젝트 상태를 분리한다. 선택하지 않은 과정이 다른 과정의 진도 분모에 포함되지 않게 한다. 현재 전역 주차 구조는 과정 범위로 확장할 필요가 있다. ([현재 진도 화면](https://github.com/meaterick/Studysite/blob/4decf9156f8c0653e651e875e7651519dbc0e44c/src/app/progress/page.tsx))

### 4.3 AI 레슨의 읽기 구성

**전체 위치·핵심 질문 → 한눈에 보는 답 → 시스템 흐름도 → 구성 개념 → 작동 원리 → 해설 예시 → 자주 생기는 오해 → 요약·관련 개념 → 선택 자기점검 → 다음 읽기** 순서로 구성한다.

긴 수식이나 코드는 핵심 설명과 선택 심화를 구별한다. 기호의 의미와 예시의 입력·출력을 함께 설명한다. 레슨 하단에서 직접 학습 완료를 표시하거나 ‘다시 보기’로 남길 수 있다.

### 4.4 대표 학습 여정

| 여정 | 이동 | 다음 행동 |
|---|---|---|
| 코딩 입문 | Python → 완성 집계기 → F1 → 기초 모듈 → F8 | 실전 활용 또는 데이터 Python |
| AI 입문 | AI → 전체 지도 → AI-01 → 관심 개념 | 다음 읽기·관련 개념 |
| AI 원리 관심 | 원리 이해 경로 → 데이터·모델·신경망·Transformer | 선택 수학·코드 해설 |
| LLM 활용 기술 관심 | LLM 경로 → 생성 → 검색·RAG → 에이전트·한계 | 비교 사례·관련 원리 |
| 기존 AI 학습자 | 기존 북마크 → 대응 지식 레슨 | 이어 읽기·기존 개인 기록 확인 |

### 4.5 공유 개념·검색·다시 보기

개념 사전에는 정의·왜 필요한지·흔한 오해·정본 레슨·관련 개념을 둔다. Python 함수 사용법과 AI 해설 코드의 함수 예시를 연결하되 본문을 중복 작성하지 않는다. 배열 API와 벡터 수학처럼 관련은 있지만 학습 목표가 다른 개념은 연결만 한다.

초기 검색은 제목·학습 목표·키워드·개념 색인으로 구성한다. AI의 다시 보기는 사용자가 표시한 레슨과 선택 자기점검을 중심으로 한다. Python은 오답·미통과 실습·약한 개념도 연결한다. 검색과 개인 기록은 과정 문맥을 유지한다.

### 5.1 분야별 레슨 명세

| 항목 | AI 지식 레슨 | Python 실습 레슨 |

| 목표 | 이해할 개념·원리·차이 1~2개 | 수행할 작업·해결할 문제 1~2개 |

| 본문 | 설명·도식·기호 풀이·비교 사례 | 최소 실행 코드·개념·수정 활동 |
| 예시 | 완성 계산·주석 코드·제공된 결과 해설 | 시작 코드·TODO·테스트·힌트 |
| 마무리 | 요약·오해 정리·개념 연결 | 독립 적용·테스트·설명 |

| 진행 | 직접 학습 완료 표시 | 공개한 실습·프로젝트 기준 |

### 5.2 Python 레슨 예시: 조건을 만족하는 기록을 집계한다

**위치:** PY-F의 F4, 선수 F2/F3. **성과:** 목록의 각 항목을 조건으로 선택하고 누적 결과를 계산한다. **산출물:** 기준 시간 이상인 작업의 총 시간과 건수를 반환하는 작은 함수의 준비 로직. 함수 문법 자체는 F5로 연결하고 이 레슨에서는 제공된 틀을 사용한다.

| 수업 장면 | 제공할 내용·학습자 행동 | 확인할 증거 |
|---|---|---|
| 완성 결과 | 작업 시간 `[20, 40, 60]`, 기준 40이면 합계 100·건수 2인 화면 | 무엇이 입력·조건·출력인지 구별 |
| 최소 실행 | 세 항목을 순회하고 조건을 만족하면 누적하는 완성 예제 | 실행 전 출력 예측 후 실제 결과 비교 |
| 한 부분 수정 | 기준을 60으로 바꾸고 `>=`를 `>`로 바꾸기 | 경계값이 포함되는 이유를 설명 |
| 개념 이해 | 반복 변수·조건·누적 변수·초깃값을 흐름도로 연결 | 합계를 반복 안에서 초기화하면 생기는 오류 해석 |
| 독립 실습 | 새 기록과 빈 목록을 받아 같은 규칙으로 집계하는 TODO | 정상·경계·빈 목록 테스트 통과 |
| 회상과 연결 | “조건 검사와 누적의 순서가 중요한 이유” 설명 | 다음 F5에서 이 로직을 함수로 분리 |

첫 힌트는 기대 결과와 실제 결과의 차이, 두 번째는 확인할 변수와 위치, 마지막은 부분 코드로 제공한다. 테스트가 특정 출력 문구만 맞히는지보다 빈 목록·경계값·여러 항목에서 요구 행동을 확인하는지 검토한다. 이를 통해 실습은 문법 암기와 다음 프로젝트의 결과 사이를 잇는다.

### 5.3 AI 레슨 예시: RAG는 왜 근거가 있어도 틀릴 수 있는가

**위치:** AI-10. **이해 목표:** 검색·답변 생성·인용의 역할을 구별하고 RAG의 한계를 이해한다. **필요 배경:** 레슨 도입에서 검색과 근거를 짧게 설명한다. Python·JSON·API 수강은 필요 없다.

| 설명 순서 | 제공할 콘텐츠 | 전달할 지식 |
|---|---|---|
| 전체 그림 | 질문→검색→근거 전달→답변·인용 흐름도 | RAG가 모델의 지식만으로 답하는 방식과 다른 점 |
| 핵심 개념 | 문서 조각·검색 결과·context·근거 ID | 각 구성 요소가 맡은 역할 |
| 정상 사례 | 질문·정답 근거·답변·인용을 한 화면에 제시 | 답변과 근거의 관계 |
| 실패 사례 | 정답 문서 누락, 상충 문서, 근거 없는 단정 | 검색 실패와 생성 실패의 차이 |
| 평가 설명 | 제공된 검색/답변/거절 결과표와 해설 | 검색 점수와 답변의 정답성이 같지 않은 이유 |
| 요약 | 가능한 보완과 남는 한계 | RAG가 사실성을 자동 보장하지 않는다는 점 |
| 선택 자기점검 | “검색에 성공하면 답변도 반드시 맞는가?”와 펼침 해설 | 스스로 이해를 점검하는 참고 |

이 레슨은 제공된 사례를 읽고 이해하는 구성이다. 시스템 구현, 코드 실행, 평가셋 작성, 결과표 제출을 요구하지 않는다. 모의 응답과 실제 모델 출력은 출처·조건을 구별해 표시한다.

### 5.4 학습 완료와 평가 정책

AI의 진도는 **학습자가 관리하는 읽기 진행**이다. 완료 표시가 지식 숙련이나 실무 능력을 인증하는 것으로 해석되지 않게 한다.

| 상태 | AI | Python |
|---|---|---|
| 학습 중 | 읽던 위치·최근 접근 | 자료·예제 학습 중 |
| 학습 완료 | 사용자가 직접 표시·해제 | 핵심 확인·대표 필수 활동 기준 |
| 다시 보기 | 사용자가 표시한 레슨 | 오답·재시도·표시한 레슨 |
| 자기점검 | 선택, 정답·해설 확인; 완료·접근과 무관 | 목표에 맞는 확인 문제 |
| 실습 통과 | 해당 없음 | 공개 행동 기준·테스트 충족 |
| 프로젝트 제출·검토 | 해당 없음 | Python 프로젝트에 적용 |
| 과정·경로 완료 | 공개된 핵심 레슨의 직접 완료 표시 집계 | 공개 핵심 모듈·프로젝트 기준 |

AI는 점수, 필수 퀴즈, 진단 통과, 코드 테스트, 제출·검토를 접근·완료 조건으로 사용하지 않는다. 모든 지식 레슨을 자유롭게 열 수 있고 추천 순서만 안내한다. 선택 심화는 핵심 읽기 진도에서 제외한다.

Python의 기존 실습·프로젝트 정책은 유지한다. 신규 Python 레슨은 핵심 확인과 대표 필수 실습을 기본 완료 조건으로 제안한다. Python 프로젝트의 초기 루브릭은 기능 40, 경계·오류 처리 20, 테스트·재현성 20, 설명·가독성 20이다. 필수 행동 기준과 영역별 요건을 우선하고 점수 통과선은 파일럿에서 확정한다.

현재 저장소의 단계 완료는 확인 문제와 핵심 단계 중심이지만, 새 AI는 지식형 완료 정책을 별도로 적용한다. 과거 완료·점수 기록을 새 정책으로 재계산하지 않는다. ([현재 완료 규칙](https://github.com/meaterick/Studysite/blob/4decf9156f8c0653e651e875e7651519dbc0e44c/src/lib/study.ts))

### 5.5 학습 환경

AI 기본 학습에는 웹 브라우저만 필요하다. 도식·수식·해설 코드·제공된 결과를 읽는 데 API 키, GPU, Colab, Python 설치가 필요하지 않다. 예시 코드의 실행은 독자가 원할 때 참고할 별도 자료이며 읽기 완료와 연결하지 않는다.

Python은 브라우저 기초 실습, 로컬 파일·API 작업, 선택 노트북 실습을 구분한다. 레슨 시작 전에 지원 패키지·저장 위치·설치·샘플 데이터·대체 자료를 안내한다. 현행 Pyodide·IndexedDB 기반을 활용하되 실제 파일·패키지 지원 범위는 구현 시 확인한다. ([현행 기술 구조](https://github.com/meaterick/Studysite/blob/4decf9156f8c0653e651e875e7651519dbc0e44c/docs/development/architecture.md))

프로젝트·루브릭·코딩 선수조건을 모든 과정의 필수 필드로 두지 않는다. 학습 방식에 맞는 정보와 화면만 표시한다.

AI 작성 흐름은 초안 → 내용 정확성·용어·설명 순서 검토 → 도식·수식·예시·출처 확인 → 공개다. 해설 코드와 제공 결과의 정확성은 작성자가 확인한다. 이는 학습자에게 테스트를 수행하도록 요구하는 절차가 아니다.

Python은 시작 코드·테스트·힌트·모범답안·루브릭 검증을 유지한다. 두 분야 모두 ID 중복·내부 링크·누락·미공개 자료 노출을 확인하고 생성 문서를 동기화한다.

### 6.4 URL과 기존 개인 기록의 이전

현행 기록은 주차·단계·셀·과제에 연결되어 있고 코드 일부는 브라우저에 저장된다. 따라서 이전 항목→전역 고정 ID→새 위치 매핑이 필요하다. 기존 기록의 근거와 버전을 유지하고 신규 AI 읽기 기록과 구분한다. ([학습 저장](https://github.com/meaterick/Studysite/blob/4decf9156f8c0653e651e875e7651519dbc0e44c/src/lib/learningStore.ts), [DB](https://github.com/meaterick/Studysite/blob/4decf9156f8c0653e651e875e7651519dbc0e44c/src/lib/db.ts), [코드 저장](https://github.com/meaterick/Studysite/blob/4decf9156f8c0653e651e875e7651519dbc0e44c/src/lib/codeStore.ts))

| 항목 | 이전 정책 |
|---|---|
| 기존 주차·이론 레슨 URL | 대응 지식 레슨 또는 호환 개요로 연결 |
| 기존 AI 과제·캡스톤 URL | 기존 개인 제출 기록 보기 또는 보관 안내로 연결; 새 제작 화면은 만들지 않음 |
| 기존 AI 점수·제출·첨부·피드백 | 원래 권한과 당시 문제·루브릭을 유지하는 읽기 전용 이력 보관 |
| 기존 AI 완료 | 당시 기준 완료 이력을 보존; 내용 대응이 명확한 레슨만 출처 표시와 함께 매핑 |
| 새 AI 읽기 진도 | 직접 완료 표시 정책으로 별도 관리; 과제 점수에서 이해도를 추정하지 않음 |
| 분할된 새 레슨 | 과거 완료를 모든 새 레슨에 자동 복제하지 않고 명시적 매핑 |
| 기존 브라우저 코드·초안 | 기기별 호환 읽기·지연 이전; 기록 삭제 없이 보존 |
| Python 기록 | 실습·제출·점수·피드백의 기존 문맥 유지 |
| 검색·내 학습 | AI 새 과제 카드는 제외; 과거 이력은 개인 기록에서만 접근 |

기존 AI 기록 보관은 새 AI 과정의 제출·채점 기능을 운영한다는 뜻이 아니다. 과거 개인 자료를 공개 사례로 자동 전환하지 않는다. 운영 데이터는 이번 기획에서 조회하거나 수정하지 않았으며, 실제 이전은 백업·매핑 점검·권한·건수 대조·중복 방지·복구 절차를 별도로 검증한다.
