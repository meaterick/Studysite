# Studysite 탑다운 커리큘럼 재설계

**권장 기본안: Python 6모듈·24레슨 + AI 6모듈·24레슨.**

학습 순서를 **“기초를 모두 배운 뒤 결과를 이해하기”에서 “익숙한 결과를 먼저 보고, 필요한 원리로 내려가기”로 바꾼다.** Python은 작은 프로그램을 바로 실행하고 점차 확장한다. AI는 익숙한 활용 장면과 시스템 구조를 먼저 이해하고, 그다음 데이터·학습·평가 원리를 설명한다. 어려운 수학·문법·모델별 심화는 해당 질문이 생긴 위치에서 선택해 읽는다.

AI는 지식 전달형을 유지한다. 캡스톤·프로젝트·필수 구현·과제 제출·채점은 넣지 않는다. Python은 실습 중심이지만 입문 과정의 마지막을 대형 프로젝트와 검토 대기로 막지 않는다.

검토 기준은 main의 51c0f485fbc50d9cd8ab420a28720b9f47e532c2다. 현재 저장소의 구현된 커리큘럼은 기존 8주 AI이며, 앞서 병합한 Python 16모듈·AI 12모듈은 기획안이다. 이번 안은 그 수와 순서를 새로 설계한 제안이며 사이트 구현 완료를 뜻하지 않는다. ([기존 커리큘럼](https://github.com/meaterick/Studysite/blob/51c0f485fbc50d9cd8ab420a28720b9f47e532c2/docs/curriculum/README.md), [직전 기획안](https://github.com/meaterick/Studysite/blob/51c0f485fbc50d9cd8ab420a28720b9f47e532c2/docs/product/learning-platform-plan.md))

## 1. 처음에는 시작 경로 하나만 제시한다

### 전체 학습 구조

    Studysite
    ├─ Python으로 작은 프로그램 만들기
    │  ├─ 기본: 첫 실행 → 조건 → 여러 값 → 기록 구조 → 함수 → 검증·응용
    │  ├─ 선택: 파일 자동화·외부 데이터
    │  └─ 선택: 표 데이터·숫자 배열
    ├─ AI가 작동하는 방식 이해하기
    │  ├─ 기본: 전체 지도 → LLM 동작 → 시스템 연결 → 학습 → 평가 → 한계
    │  └─ 선택: 모델 지도·학습 계산·신경망 내부·평가와 운영
    └─ 공통: 학습 지도·개념 검색·내 학습·다시 보기

| 설계 항목 | 결정 |
|---|---|
| 첫 화면 | ‘Python 시작하기’, ‘AI 이해하기’ 두 선택과 최근 학습 이어가기 |
| 기본 순서 | 분야별 기본 과정 하나. 처음부터 여러 과정을 비교하도록 요구하지 않음 |
| 내부 분류 | 분야 → 과정 → 모듈 → 레슨. 학습 경로는 기존 레슨을 참조하는 목록 |
| 실제 이동 | 분야 화면에서 첫 레슨으로 바로 시작. 과정·모듈 소개를 모두 거치게 하지 않음 |
| 전체 목차 | 언제든 열 수 있고 아는 내용은 건너뛸 수 있음 |
| 선택 학습 | 본문 옆 ‘더 알아보기’. 기본 경로 완료에 포함하지 않음 |
| 분야 간 관계 | Python과 AI는 독립적으로 시작. Python 수료가 AI의 조건이 아님 |

### 분야별 탑다운 방식

| 단계 | Python | AI |
|---|---|---|
| 전체 먼저 | 완성 출력과 프로그램의 쓰임 관찰 | 분류·예측·추천·생성 사례와 전체 흐름 관찰 |
| 작은 부분 | 현재 목표를 처리하는 몇 줄 코드 | 한 질문을 설명하는 작은 시스템 그림 |
| 행동·이해 | 예측 → 실행 → 값·조건 변경 | 사례 → 필요한 용어 → 작동 원리 해설 |
| 깊이 확장 | 도움이 줄어드는 짧은 문제 | 비교·오해·한계, 선택 수식·코드 풀이 |
| 마무리 | 새 입력이나 작은 새 요구에 적용 | 핵심 요약·개념 연결·선택 자기점검 |

‘탑다운’은 거대한 완성 프로그램이나 복잡한 모델 구조를 첫날 전부 읽히는 방식이 아니다. **결과는 먼저 보여주되, 현재 이해할 코드와 개념은 작게 제공한다.**

## 2. Python 기본 과정은 작은 프로그램 하나를 확장한다

### 과정의 목표

- 목표: 자료를 담고, 조건으로 고르고, 반복 계산하고, 함수로 재사용하는 작은 프로그램을 스스로 수정한다.
- 일관된 사례: **지출 기록 요약기**. 첫날은 두 금액을 더하고, 마지막에는 분류별 지출을 함수로 요약한다.
- 완성 모습은 “총 지출 / 예산 상태 / 교통비 합계”처럼 출력으로 미리 보여준다. 전체 소스를 처음부터 펼치지 않는다.
- 새 문법은 현재 프로그램에 새 요구가 생기는 순간 도입한다.

### 핵심 6모듈·24레슨

| 모듈·질문 | 세부 레슨 4개 | 프로그램의 변화 | 작은 확인 |
|---|---|---|---|
| **P1 내 첫 프로그램** — 오늘 쓴 돈을 바로 합칠 수 있을까? | ① 완성 출력과 입력→처리→출력 ② 4줄 코드 실행하기 ③ 값 하나 바꾸고 결과 예측하기 ④ 잘못 쓴 이름·기호 고치기 | 두 금액의 합계 출력 | 새 금액의 결과를 예측하고 오류 하나 수정 |
| **P2 상황에 따라 판단하기** — 예산을 넘으면 알려줄 수 있을까? | ① 숫자와 문자열의 차이 ② 비교와 True/False ③ if/else로 예산 판단 ④ 경계값과 읽기 좋은 출력 | 합계·예산·상태 표시 | 예산보다 작음·같음·큼 확인 |
| **P3 여러 지출 처리하기** — 지출이 20개라면? | ① list로 여러 값 담기 ② for로 하나씩 보기 ③ 합계·개수 누적 ④ 조건에 맞는 항목 선택 | 길이가 다른 목록 요약 | 빈 목록·한 항목·여러 항목 확인 |
| **P4 의미 있는 기록 다루기** — 금액과 분류를 함께 기억하려면? | ① dict의 이름과 값 ② list 안에 기록 모으기 ③ 원하는 분류만 선택 ④ 기록 추가 후 결과 추적 | 금액·분류가 있는 기록 요약 | 새 분류·새 기록에도 같은 로직 사용 |
| **P5 기능으로 나누기** — 다른 기록에도 같은 계산을 쓰려면? | ① 반복된 코드를 함수로 묶기 ② 매개변수와 반환값 ③ print와 return 구별 ④ 기능 두 개를 연결 | 합계·필터 함수를 재사용 | 다른 두 목록에 같은 함수 적용 |
| **P6 믿고 바꾸기** — 새 요구가 생겨도 틀리지 않으려면? | ① 기대 결과를 먼저 적기 ② assert로 정상·빈 값·경계 확인 ③ 실패 위치를 좁혀 수정 ④ 같은 패턴을 다른 기록에 적용 | 검증 가능한 작은 요약 프로그램 | 고장 하나 수정 후 학습시간 기록 같은 짧은 새 문제 해결 |

**선수 관계:** P1 값·실행 → P2 조건 → P3 목록·반복 → P4 구조화 기록 → P5 함수 → P6 검증·응용.

- P3에서 list와 for를 사용한 뒤 P4에서 dict를 추가한다. 자료구조 전체를 한 번에 나열하지 않는다.
- 이미 잘 동작하는 코드가 반복되는 모습을 본 뒤 함수를 도입한다. 필요성을 이해한 다음 문법을 배운다.
- 오류 읽기는 P1부터 반복한다. P6은 오류를 처음 소개하는 장이 아니라 검증 방법을 정리하는 장이다.
- P6은 짧은 전이 문제다. 새로운 문법·장문의 보고서·발표·대형 캡스톤은 필수로 두지 않는다.

### 첫 레슨의 실제 크기

    meal = 8000
    bus = 1500
    total = meal + bus
    print(total)

학습자는 9500이라는 결과를 보고, 식비를 바꾸기 전에 새 결과를 예상한 뒤 실행한다. 여기서 설명할 것은 이름·값·더하기·출력뿐이다. 함수·목록·import·설치·사용자 입력을 동시에 도입하지 않는다.

| 진행 | 제공할 도움 | 학습자가 하는 일 |
|---|---|---|
| 처음 | 완성 코드·입출력 화살표 | 값 하나 변경 |
| 조금 익숙해짐 | 예제와 조건·계산식 빈칸 | 필요한 식이나 조건 채우기 |
| 기능 연결 | 구조 일부와 입력 예시 | 필터·함수·반환값 연결 |
| 마지막 | 짧은 요구와 기대 출력 | 배운 패턴으로 작은 기능 수정·검증 |

### 목적이 생기면 고르는 선택 확장

| 선택 모듈 | 시작 질문 | 다룰 내용 | 필요한 기본 |
|---|---|---|---|
| **PY-A1 파일 자동화** | 매번 기록을 코드에 붙여 넣지 않으려면? | CSV 결과 보기 → 경로·파일 읽기 → 기록 변환 → 요약 저장 → 누락·빈 파일 | P4/P5 |
| **PY-A2 외부 데이터** | 웹의 자료를 같은 방식으로 요약하려면? | 고정 JSON → 요청·응답 → 값 추출 → 오류·시간초과 → 키·환경 | P4/P5 |
| **PY-D1 표 데이터** | 기록이 많으면 표로 어떻게 볼까? | 요약표·그래프 → DataFrame → 필터·집계 → 결측·중복 → 해석 | P4/P5 권장 |
| **PY-D2 숫자 배열** | 숫자를 묶어 계산하면 무엇이 달라질까? | 배열·shape → 인덱싱 → axis·집계 → broadcasting → 행렬곱 | 목록·반복·함수 호출 읽기 |

- 두 확장 방향을 모두 끝낼 필요는 없다. 표 데이터를 보기 위해 NumPy 전체를 먼저 수료시키지도 않는다.
- 로컬 설치는 실제 파일 작업 직전, 가상환경은 외부 패키지 사용 직전에 안내한다.
- 클래스·고급 타입·데코레이터·비동기·배포는 초보 공통 핵심에서 뺀다. 필요할 때 참고 주제로 제공한다.
- 외부 데이터는 고정 응답으로도 같은 로직을 학습할 수 있게 한다. 브라우저 파일·패키지 지원은 구현 시 확인한다.

## 3. AI는 사용 장면에서 내부 원리로 내려간다

### 과정의 목표

- 목표: AI가 하는 일, 답을 만드는 과정, 주변 시스템의 역할, 모델의 학습, 성능과 한계를 이해한다.
- 기본 흐름: **전체 지도 → LLM 동작 사례 → 외부 지식·도구 연결 → 모델 학습 → 평가·실패 → 한계·책임**.
- LLM은 친숙한 설명 사례다. 첫 모듈에서 분류·수치 예측·추천·생성을 나란히 다뤄 AI 전체와 구별한다.
- Python·수식 계산·API 계정 없이 읽을 수 있다. 구현·프로젝트·제출·채점은 없다.

### 핵심 6모듈·24레슨

| 모듈·질문 | 세부 레슨 4개 | 제공할 사례·그림 | 이해할 핵심 |
|---|---|---|---|
| **A1 AI의 전체 지도** — AI는 무엇을 하는가? | ① 분류·예측·추천·생성 비교 ② 입력→표현→모델→출력 ③ 학습과 추론 구별 ④ AI·ML·DL·생성형 AI·LLM 관계 | 스팸·가격 예측·추천·문장 생성, 학습/추론 두 경로 | AI를 LLM과 동일시하지 않고 학습과 사용을 구별 |
| **A2 LLM의 답변 생성** — 질문이 어떻게 답이 되는가? | ① 텍스트의 토큰·숫자 표현 ② 문맥 정보를 연결하는 구조 ③ 다음 토큰 확률과 반복 생성 ④ 문맥 길이·생성 설정·환각 | 토큰 흐름도, 확률 그림, 같은 질문의 다른 응답 | 그럴듯한 생성과 사실 확인의 차이 |

### 이 순서가 끊기지 않게 만드는 연결

| 위치 | 먼저 설명할 최소 배경 | 뒤에서 확대할 내용 |
|---|---|---|
| A1 | 학습 때 모델이 바뀌고 추론 때 사용한다는 직관. 유창함과 정확함은 다름 | A4 학습, A5 평가 |
| A2 | 이미 학습된 LLM을 쓰는 추론 사례임을 명시 | 학습 방법은 A4, QKV 계산은 선택 해설 |
| A3 | 임베딩은 의미 관계를 나타내는 위치 그림으로 즉시 풀이 | 행렬·검색 알고리즘은 선택 해설 |
| A3→A4 | “지금 사용한 모델 자체는 어떻게 만들어졌을까?” | 데이터·손실·갱신 원리 |
| A4→A5 | “학습 후 정말 더 좋아졌는지 어떻게 알까?” | 분할·지표·실패 분석 |
| A5→A6 | “점수가 높아도 실제 사용에 남는 문제는?” | 개인정보·책임·비용·변화 |

- 정확성·근거·권한의 한계를 A5/A6까지 미루지 않는다. A1/A2에는 틀린 답 사례를, A3에는 자료 없음·도구 권한의 경계를 먼저 짧게 둔다.
- 모든 AI가 다음 토큰을 생성한다고 설명하지 않는다. A2는 LLM의 동작 모델이다.
- RAG로 문서를 붙이는 것과 가중치를 바꾸는 학습을 구별한다.
- 손실·가중치 갱신은 회귀·신경망을 설명하는 예시다. 트리·군집 등은 모델에 맞는 규칙·구조를 학습하므로 모든 AI가 같은 방식으로 갱신되는 것은 아니다.
- 제공된 수치·코드·결과는 해설 자료다. 학습자가 계산·실험·평가표를 작성해야 하는 활동으로 바꾸지 않는다.

### 깊이가 필요한 독자를 위한 선택 해설

| 독자의 질문 | 해설 묶음 | 구체 주제 | 본문 연결 |
|---|---|---|---|
| 데이터와 문제에 따라 어떤 모델을 쓰는가? | **모델의 작은 지도** | 회귀·로지스틱 / 트리·RF·부스팅 / 군집·추천·차원 축소 / 신경망·CNN·Transformer | A1·A4 |
| 손실이 줄어드는 과정을 숫자로 보고 싶다 | **학습 계산** | 벡터·내적 / 확률·교차엔트로피 / 미분·경사하강 / 계산 그래프·역전파 / 규제·최적화 | A2·A4 |
| 문맥을 연결한다는 계산은 무엇인가? | **신경망·Transformer 내부** | 뉴런·MLP / CNN 필터·수용영역 / embedding·QKV / multihead·mask·위치 / decoder·KV cache | A2·A4 |
| 비교 결과와 운영 변화는 얼마나 믿을 만한가? | **평가·운영 심화** | 편향·분산·CV / 검색·답변·거절 / judge 평가 한계 / 재현성·ablation / 버전·드리프트 | A5·A6 |

선택 해설은 과거 주차 전체를 부록에 쌓는 방식이 아니다. 본문에서 방금 생긴 질문 하나를 링크하고, 그 해설에서 필요한 배경을 연결한다. CNN·전통 ML·수학을 삭제하는 대신 **입문 순서의 관문에서 질문별 깊이 학습으로 이동**한다.

## 4. 첫 10분과 한 레슨을 구체적으로 설계한다

아래 시간은 편집 시나리오이며 실제 학습시간 통계나 보장값이 아니다.

| 구간 | Python | AI |
|---|---|---|
| 0~2분 | 완성 출력 미리보기, 오늘은 두 금액만 계산한다고 안내 | 분류·예측·생성 사례와 전체 지도 |
| 2~4분 | 4줄 코드를 그대로 실행 | 입력→모델→출력, 학습/추론 그림 |
| 4~6분 | 금액 하나를 바꾸기 전 결과 예상 후 실행 | 같은 AI가 틀리거나 다른 답을 하는 사례 |
| 6~8분 | 변수·계산·출력과 작은 오류 풀이 | 오늘 필요한 개념과 한계만 짧게 해설 |
| 8~10분 | 다른 금액으로 같은 동작, 한 문장 정리 | 핵심 3문장·선택 질문·다음 읽기 |

### 분야별 레슨 틀

| 순서 | Python 실습형 | AI 지식형 |
|---|---|---|
| 1 | 오늘 할 일·출력·전체 위치 | 오늘의 질문·전체 위치 |
| 2 | 가장 작은 완성 코드 | 2~3문장 답과 흐름도 |
| 3 | 예측·실행·비교 | 구체 사례와 필요한 용어 |
| 4 | 한 부분 수정 | 작동 원리·해설 예시 |
| 5 | 방금 본 동작의 개념·오류 설명 | 비교·오해·한계 |
| 6 | 도움을 줄인 짧은 문제 | 핵심 요약·관련 개념 |
| 7 | 작은 확인·다음 행동 | 선택 자기점검·다음 읽기 |

**AI 대표 레슨 — “모델이 모르는 문서를 어떻게 참고할까?”**

1. 같은 질문에 모델만 사용한 답과 문서를 참고한 답을 나란히 보여준다.
2. 모델에 학습된 지식과 지금 입력에 붙인 문서를 다른 색으로 표시한다.
3. 질문 → 검색 → 관련 문서 조각 → 모델 입력 → 답변·인용 흐름을 설명한다.
4. 청킹·검색·context·인용을 등장하는 위치에서 정의한다.
5. 정답 근거 없음·상충 자료·검색 실패의 제공된 사례를 해설한다.
6. “RAG를 쓰면 항상 사실인가?”라는 선택 질문과 펼침 해설로 마친다.

이 레슨에 API 설정·JSON·코딩·자료 수집·시스템 제작을 요구하지 않는다. 자기점검을 하지 않아도 다음 레슨을 읽을 수 있다.

## 5. 화면과 진도는 다음 행동을 쉽게 찾게 한다

| 화면 | 보여줄 것 | 주요 행동 |
|---|---|---|
| 홈 | 두 분야의 학습 약속·최근 위치 | 시작 또는 이어서 |
| 학습 지도 | 기본 6모듈·현재 위치·완료 상태 | 오늘 레슨·전체 목차 |
| 레슨 | 본문·예시·필요한 짧은 풀이 | AI 읽기 / Python 실행 |
| 개념 검색 | 정의·비교·관련 레슨 | 풀이 후 원래 위치 복귀 |
| 내 학습·다시 보기 | 최근 위치·표시한 내용 | 이어 읽기·재시도 |

- 기본 경로 하나를 먼저 제시하고 선택 심화는 접어 둔다. 전체 목차와 건너뛰기는 항상 사용할 수 있게 한다.
- 사전 설명을 읽으러 이동해도 원래 레슨의 위치가 유지되어야 한다.
- AI는 본문과 도식을 중심으로, Python은 코드와 실행 결과를 중심으로 화면을 구성한다.
- 첫 레슨 전에 긴 설문·진단·개발도구 과정을 통과시키지 않는다.

| 구분 | Python | AI |
|---|---|---|
| 진행 확인 | 목표에 맞는 출력 예측·짧은 동작 확인 | 사용자가 직접 읽기 완료 표시·해제 |
| 확인 활동 | 재시도·힌트가 있는 작은 실습 | 선택 질문 1~3개와 해설 |
| 마지막 | 새 입력·새 맥락의 짧은 응용 | 전체 지도 다시 읽기·관심 심화 선택 |
| 관문 | 운영자 채점 대기를 필수화하지 않음 | 점수·필수 퀴즈·제출·코드 실행·선수 수료 없음 |

AI 읽기 완료는 진행 관리 기능이며 숙련 인증이 아니다. Python 방문과 실습 확인도 구별한다. 재시도와 힌트 사용에 벌점을 주지 않는다.

## 7. 전체 분량보다 대표 학습 경험부터 완성한다

- 새 분야·AI 튜터·랭킹·인증서·복잡한 추천보다 기본 경로와 설명의 품질을 먼저 완성한다.

### 쉬워졌는지 확인할 기준

이 설계는 입문자에게 권장하는 기본안이며, 모든 학습자에게 실증적으로 최적인 순서라고 주장하지 않는다. 실제 배경·중단·완주 데이터가 없으므로 파일럿으로 수정한다.

| 확인 질문 | 관찰할 증거 |
|---|---|
| 시작이 쉬운가? | 첫 레슨까지의 이동, 설치 이탈, 첫 실행·첫 개념 도달 |
| 설명이 연결되는가? | 갑자기 등장한 용어, 빠진 전제, 사전 이동 후 복귀 |
| Python을 따라 한 것 이상 배웠는가? | 입력이 달라진 짧은 문제에서 수정·설명 가능 여부 |
| AI 설명을 이해할 수 있는가? | 희망자와의 짧은 개념 구별·사례 해석 대화, 어려운 설명 피드백 |
| 다음 행동이 분명한가? | 다음 버튼 탐색 실패·길 잃음·다시 보기 이유 |
| 분량이 적절한가? | 예상/실제 시간, 도움 요청, 개념이 몰리는 위치 |

AI 파일럿의 이해 확인은 사이트의 의무 과제·채점으로 바꾸지 않는다. 체류시간·읽음 비율만으로 이해가 좋아졌다고 결론 내리지 않는다. 개선 폭이나 제작 기간은 실제 기준선·인력이 확인된 뒤 산정한다.
